## 控制结构

```
速度环 (外环, 慢)  ──> 目标倾角 target_pitch (°)
     │
     ▼
平衡环 (内环, 快)  ──> 电机差速 drive (%)
     │
     ▼
转向环 (并联)      ──> 左右轮差速修正 steer (%)

输入: MPU9250 姿态角/角速度 + 编码器轮速
输出: 电机 A/B PWM + 两路舵机
```

平衡靠两轮差速（坦克转向原理）调整重心，舵机不参与主平衡回路。

**当前控制周期 10ms 单环串级。** 如果实测内环响应不够快，
下一步把平衡环拆成独立的高频任务（20~50Hz），速度环留在 10ms。

## 状态机

```
IDLE ──(启动)──> STANDBY ──(倾角正常)──> BALANCING
                                          │
                                     (倾角超限)
                                          ▼
                                       FALLEN
                                          │
                                    (人把车扶正)
                                          ▼
                                       STANDBY
```

- **IDLE**：未启动，电机刹车
- **STANDBY**：已启动但还没进平衡（等姿态稳）
- **BALANCING**：控制中
- **FALLEN**：判定摔倒，电机已停、积分已清，**等扶正后自动回 STANDBY**

摔倒判定：`|pitch| > ang_limit`（参数 `ang_limit`，默认 25°）。
宁可误停（车还立着但先不跑）也不能不停（车倒了还在输出会烧电机）。

## 腿角几何补偿（实测查表）

**问题**：MPU 装在车身上，报的是「车身相对铅垂线」。但两轮车站在地上时
**轮轴被地面强制水平**，真正决定会不会倒的是「车身相对轮轴」，
而这个角度**由腿弯曲多少决定**。所以腿一弯，站立目标就偏了。

**修法**：在信号侧减掉腿带来的那部分：

```
pitch_修正 = pitch_原始 + ang_zero − 补偿(φ)
补偿(φ)    = pitch(φ) − pitch(φ_home)        ← 查表插值得到
```

- `φ` = 当前舵机逻辑角（两路镜像，共用一个自由度）
- `φ_home` = 舵机中心角 `servo_c`
- `ang_zero` 继续管「MPU 焊歪的固定角」，两者分工不冲突

**在信号侧而不是目标值上**：这样摔倒判定（`|pitch| > ang_limit`）也会跟着被修正，
否则腿弯多了会误判摔倒。

### 为什么用实测查表，不用四连杆运动学

解析运动学要 4 根杆长 + 铰接点坐标，但：杆长测量有误差、打印件有形变、
销孔有间隙 —— 5% 的杆长误差在死点附近会被放大到腿高 20% 的误差。
**实测查表量的是真实世界，把这些误差全都包含进去了**，对配平用途远优于推算。

### 三级降级（不标定也能安全跑）

| 优先级 | 方案 | 何时启用 |
|---|---|---|
| 1 | 查表（`user/legmap`） | 标定了 ≥2 个点且曲线形状正常 |
| 2 | 线性 `leg_k` | 查表不可用，且 `leg_k ≠ 0` |
| 3 | 不补偿 | 都没数据（= 最初版本行为） |

> 线性只能拟合直线。实测的 `Pitch~腿角` 常常是 U 型，
> 直线拟合残差可达变化幅度的 **53%**，丢一半补偿量。
> 所以优先用查表，`leg_k` 只作为兜底（可用 `/api/legmap_fit_legk` 从标定点反推）。

### Kp 按腿高调度

```
Kp_eff = bal_kp + kp_hslope × (腿高 − kp_href)
```

物理依据：腿长 → 重心高 → 绕轮转动惯量大。同样的 Kp 在高腿位下阻尼不足，
车会发软振荡。限幅 `[0, 200]`。

> ⚠ **`kp_hslope` 没有通用值，必须自己试车标定**：
> 在站不起来的那个腿高把 Kp 加到不晃为止并记下，换腿高再记一次，
> 两次差值 ÷ 高度差 = 斜率（方向反了取负）。默认 0 = 不调度。

> 舵机是**开环**的（只写 PWM，无位置回读），φ 是指令角不是实际角。
> 查表方案因为纵轴也是实测的，这部分误差已在标定数据里部分体现，
> 但常值残差仍需平衡环的 Ki 兜住。

### 标定步骤（网页「腿高标定」面板）

> ⚠ 标定时**必须把车固定住**（放桌上 / 夹具 / 手扶），全程不要落地。
> 工具会自动强制刹车并停掉平衡控制，电机不会转。
> 关键：**只让腿动，车身不能动**，这样测出的差值才是「腿的贡献」。

1. 点「清空重来」
2. 腿角设 30° → 点「**动腿并读取**」（ESP32 等稳定 1 秒后读 Pitch）
3. **拿尺子量轮心离地高度**，填进「实测腿高」框
4. 点「**录入这个点**」→ 重复 40 / 50 / 60 / 70 / 80 / 90 / 100°（6~8 个点铺满行程）
5. 网页实时提示点数、腿角跨度够不够、高度是不是在乱抖
6. 录完点顶部「**保存到 NVS**」才落盘

> ESP32 能读 Pitch 但**量不了自己的腿高**，所以高度必须你手动量，这是流程半自动的原因。

**曲线形状检查**：腿高对角度必须是**单峰**的（先降后升，最多 1 个拐点）——
这正是四连杆的真实形状。拐点 > 1 说明尺子读错了，网页会报警要求重录。

详细原理和踩坑见 `../logs/2026-10-05.md`。

## HTTP 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/` | 调参主页 |
| GET | `/api/params` | 取全部参数 |
| POST | `/api/params` | 批量设参数 |
| POST | `/api/save` | 保存到 NVS |
| POST | `/api/reset` | 恢复默认（仅内存） |
| GET | `/api/status` | 实时状态（含 `bal_state` / `tgt_pitch` / `bal_out` / `mot_a` / `mot_b`） |
| POST | `/api/balance` | 启停平衡控制，body `{"on":1\|0}` |
| POST | `/api/balance_stop` | 急停（清 PID 积分） |
| POST | `/api/balance_reload` | 重读 param 里的控制参数 |
| POST | `/api/motor` | 电机手动测试，body `{"on":1,"speed":40,"dir":1}` |
| POST | `/api/stop` | 急停电机 |
| POST | `/api/servo` | 舵机回中 |
| GET | `/api/legmap` | 取腿高标定表 |
| POST | `/api/legmap` | 录入腿高点，body `{"act":"clear\|move\|read\|add","deg":80,"h":61.5}` |
| POST | `/api/legmap_fit_legk` | 用标定点反推线性 `leg_k`（兜底方案） |
| POST | `/api/reboot` | 重启 |

## 屏上平衡控制页

菜单第 1 项。显示状态机状态 + 串级各环中间量：

```
BALANCE CTRL
St:  IDLE OFF
Pit:  -0.15 g   1.2
Tgt:   0.00 deg
Bal:   0.0 %
Spd:   0.0 S  0.0
Mot: A   +0 B   +0
Whl:   0.0 rpm
------------------------------
[K1]Bk [K2]On/Off
[K3]E-Stop (clr int)
```

K2 启停，K3 急停（清积分），K1 回菜单。进入/退出该页都会自动停机。
