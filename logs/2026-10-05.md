# 2026-10-05 开发日志

## 腿弯曲导致 MPU 读数偏移：加腿角几何补偿 + 标定工具

**用户反馈**：MPU9250 的 Y 轴指向俯仰角，但小车平衡时 MPU 的摆放不是水平的，
具体角度会根据腿的弯曲程度改变。

### 一、先把问题定位清楚（这一步最花时间，但决定了方案）

用户补充的机械信息（问过 4 个问题确认）：

| 事实 | 值 |
|---|---|
| MPU 安装位置 | 车身上，和两个舵机在一个水平面 |
| 能否挪位置 | **不能**（结构限死） |
| 腿的角色 | **主动参与平衡**（但当前版本先做静态） |
| 平衡时腿动不动 | 现在不动，以后会做动态 |

**关键认知修正**：一开始我以为问题出在"测量"上，错了。

两轮车站在地上，**轮轴被地面强制水平**。所以：

- 轮轴相对铅垂线 ≈ 恒定 0°
- 变的是**车身相对轮轴**的角度，而这个角度**完全由腿弯曲程度决定**

MPU 装在车身上，报的是「车身相对铅垂线」——**这个测量本身没错**。
真正的问题是：

> 控制器把「车身 pitch = 0」当成站立目标，但真实的站立目标是
> 「车身相对轮轴 = 某个随腿弯曲而变的角度」。

现有 `PARAM_ANGLE_ZERO` 是个**常量**，只能配准**一个**腿的角度。
腿一弯目标就偏，`ang_zero` 配平就失效。

于是 pitch 读数分解成三项：

```
pitch_MPU = 车身相对轮轴角(要的) + 腿弯曲带来的 + MPU焊歪的固定角
             └─ 被 leg_k 补偿 ─┘        └─ 被 ang_zero 补偿 ─┘
```

### 二、方案：加一个参数 `leg_k`

**只加 1 个新参数**（`leg_k`，单位 °/°），`φ_home` 复用现有的 `PARAM_SERVO_CENTER`
（舵机中心角），不新增。修正放在**信号侧**：

```c
pitch_修正 = pitch_原始 + ang_zero - leg_k * (φ - φ_home)
```

`leg_k = 0`（默认）时整个项退化为 0，**行为和加补偿之前完全一致**，所以不标定也能安全跑。

**为什么放信号侧而不是加在目标倾角上**（这是个设计决策，记一下理由）：

1. 摔倒判定 `balance_check_fallen()` 判的是 `|pitch|`。放信号侧则判定**跟着一起被修正**，
   否则腿弯多了会误判摔倒。放目标值上判定不会跟着变。
2. 目标倾角就干干净净只剩"想让它倾斜多少"（速度环输出），语义清晰，不和配平值混在一起。

**局限性（必须知道）**：舵机是**开环**的（`servo_set_angle()` 只写 PWM，没有位置回读），
拿到的 φ 是"指令角"不是"实际角"，腿受力变形会造成误差。
但这只是个**前馈平移量**，常值误差由平衡环的 Ki 自己吃掉，不需要精确模型。

### 三、顺手修的 2 个真实 bug

这两个不管最后用哪种方案都得修，用户也确认了"一起改"。

#### Bug 1：一个控制周期读了两次 I2C

`balance_read_sensors()` 原来分别调 `mpu9250_get_euler_angle()` 和
`mpu9250_read_gyro()`，这是**两次独立的 I2C 事务**，数据不同时刻。

**危害**：平衡环的 D 项（角速度阻尼）依赖姿态角与角速度的**严格对应关系**。
错位会让阻尼失准，10ms 周期下误差不小。

**修法**：新增 `mpu9250_get_pose(euler, gyro)` 一次读同时出两个，
`balance_read_sensors()` 改用它。旧的 `get_euler_angle()` 保留为兼容包装（内部也只读一次）。

#### Bug 2：互补滤波的 dt 硬编码 `0.01f`

```c
float dt = 0.01f;              // 假设 100Hz
current_angle.pitch += data.gyro.y * dt;
```

**危害**：控制周期一改，陀螺仪积分就错，而且**没有任何提示**，静默算错。

**修法**：改用 `esp_timer_get_time()` 实测两次调用的真实间隔，并夹住上限 100ms
（防止跨设备复位 / 长时间空档时 dt 异常大导致积分发散）。

**踩坑**：加 `esp_timer.h` 报 `No such file or directory`。
按 10-04 日志记的老办法处理——`idf_component_register(REQUIRES esp_timer)`，
然后**删 `.pio/build/<env>/CMakeCache.txt` 重编**才生效。

#### 附带修：I2C 并发保护

`mpu9250_read_data()` 是对外独立接口，控制任务和 UI 页可能同时调用，
两条 `i2c_master_*` 并发操作同一总线会拿到互相穿插的数据。
在底层加 `portMUX` 临界区。代价约 0.4ms（400kHz 下读 14 字节），可接受。

### 四、标定工具（网页，方案 C）

用户选了"网页手动拨腿 + 自动算斜率"。

**为什么这么测才安全且准**：关键在**车身固定不动，只让腿动**。
- 电机全程刹车 + 强制停平衡控制（接口里有安全闸门，每次调用都执行）
- 车放桌上 / 夹具固定 / 手扶
- 这样 Pitch 的变化纯粹来自"腿在动"，混不进地面不平、轮子打滑的干扰
- **全程车一动不动，不存在摔倒风险**

**采样策略**：每个腿角停留 300ms 等姿态稳，连采 30 次求平均，压掉互补滤波残余抖动。
默认建议 5 个点（35/50/65/80/95°）。

**拟合用最小二乘**而不是两点差值：单点差值带噪声，残差还能反映"读数稳不稳"。

**实现细节**：
- `POST /api/legcal`，body `{"act":"reset|move|sample|fit","deg":80}`
- 新增 `json_str()` 工具函数（原来只有 `json_num()`）
- `max_uri_handlers` 16 → 18（原值 16 已接近上限，加路由容易静默失败）

#### 踩坑：退化检查写错了（已修）

第一版用 `fabsf(den) < 1e-6` 判断"腿角拉不开"，**这个检查根本不起作用**。

`den = n·Σx² − (Σx)²` 是**平方和量级**，实测 5 个点全挤在 80~81°
（跨度只有 1°）时 `den = 38884`，永远不接近 0，
结果会算出 `k = 噪声/1°` 这种巨大的假斜率。

**改成判断腿角跨度**：`xmax - xmin < 20°` 直接拒绝。这个检查才真正拦得住。

（这个 bug 是用合成数据离线跑拟合公式验证时发现的，不是靠肉眼看出来。）

### 五、俯仰角实时波形图

用户要求加。画两条线：

- **绿线 = 原始 Pitch**（反推：`修正后 + 腿角补偿`）
- **黄线 = 修正后 Pitch**（零偏和腿角补偿都扣掉）

标定时看绿线随腿角怎么走；补偿配好后应该看到黄线被拉平。

**⚠ 重要局限（已写进代码注释和网页说明）**：
采样源是 `/api/status` 轮询，**500ms 一次**，所以画的是**趋势线**，
抓不到 10ms 级的姿态抖动。要看真实 100Hz 波形必须走串口。
用户已确认接受这个精度（选"网页就行"）。

顺带：修 Bug 1 之前，Pitch 和 gx 的波形会有肉眼可见的错位抖动；修好之后应该平滑很多。
所以这个图不只是好看，是**诊断工具**。

### 八、使用方法（待用户烧录验证）

1. `pio run -t upload`
2. 手机连热点 `BalanceRobot_XXXX`，浏览器开 `http://192.168.4.1`
3. 展开「腿角标定工具」：
   - **把车放桌上或夹具固定住，手扶也行，全程不要落地**
   - 点「清空重来」
   - 腿角滑块设 35° → 点「动腿到该角度」→ 扶稳 → 点「采一个点」
   - 重复 50 / 65 / 80 / 95°
   - 或者直接点「自动补满 5 点」（每个点间隔 1.2 秒）
4. 点「算出 Leg K 并填入」→ **再点顶部「保存到 NVS」才落盘**
5. 展开「俯仰角波形」看绿线是否随腿角线性变化

### 九、判断标定结果准不准

- **K 接近 0** → 网页会提示"MPU 位置几乎不受腿影响，补偿意义不大"，
  这时把 `leg_k` 留 0 即可，不用补偿
- **残差 > 0.5°** → 网页会提示重采，通常是采样时车动了或腿角没拉开
- **看波形图**：补偿配好后，从不同腿角出发，黄线应该基本重合

### 十、遗留 / 后续

- 标定的 `leg_k` 是**开环估算**（舵机无位置回读），真机试车后如果发现
  配了补偿仍有稳态偏差，可以先用平衡环的 `Ki` 顶一下，后续再考虑
  给腿加位置传感器
- 用户说以后腿会做**动态**（平衡时持续摆动）。当前实现已经支持
  ——补偿项每周期跟着 `servo_get_angle()` 实时更新，腿动就自动跟着补偿。
  但动态腿场景下 `leg_k` 的精度要求会高很多，可能需要重新评估
- 平衡环的 PID 输出**仍然没接到电机**（骨架版的既定安排），
  本次改动只涉及测量和设定值链路，不影响这个状态
- `ui_balance.c` 屏上页还没显示 `leg_comp`，暂时只在网页上看得到。
  屏上 128x160 已经很挤，等需要时再加
