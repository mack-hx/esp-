# 2026-10-13 开发日志

## 新增: 1.4 设备激活 — WiFi STA 模式 + OneNet MQTT 上线

### 一、背景
1.3 写完后用户问"设备怎么激活使用"。查 OneNet 官方文档确认:
- OneNet **没有"激活"按钮**, 设备首次 MQTT CONNECT 成功 = 自动激活上线
- 1.3 的 `wifi_ap.c` 只实现 AP 模式 (开 `BalanceRobot_XX` 热点), 设备**联不了外网**,
  自然连不上 `mqtts.heclouds.com:1883`, 永远离线 = 永远不激活

### 二、用户决策
经几轮 AskQuestion, 用户最终选择:
- 网络模式: **STA 模式** (连家里 WiFi, 设备才能上外网)
- 配网方式: **AP 配网** (NVS 没存 WiFi 时开 `BalanceRobot_Setup_XX` 热点, 手机连上后浏览器填一次)
- AP 网页范围: **只做配网, 不做调参** (调参改走 OneNet App)
- 版本: 复制 1.3 → 1.4, 在 1.4 里改 (保留 1.3 稳定)

### 六、关键设计

#### 1. 配网页协议 (极简)
- `GET /` → 返回 HTML 表单
- `POST /api/wifi` body `{"ssid":"...","pass":"..."}` → 存 NVS → 返回 `{"ok":true}` → 500ms 后软重启
- 配网页只在 AP 模式打开, STA 模式下 `BalanceRobot_Setup_XX` 热点会消失

#### 2. WiFi 模式
- NVS 有 `ssid` + `pass` → `WIFI_MODE_APSTA` (STA 连家里 WiFi, AP 仍开做兜底)
- NVS 没有 → `WIFI_MODE_AP` (开配网热点, STA 不连)
- STA 5 次重试失败 → 状态进 WIFI_STA_FAILED, 屏幕上提示 `<not saved>`

#### 3. 与 OneNet 配合
- `mqtt_client_start()` 在 `wifi_sta_start()` 之后, STA 还没连时 mqtt 内部自己会重试
- 屏上 ui_netstat 页同时显示 WiFi 和 OneNet 两路状态

#### 4. 重新配网
- UI 上 K4 单按 → `wifi_sta_reprovision()` → 清 NVS → 软重启
- 设备下次启动又会开 `BalanceRobot_Setup_XX` 热点

### 七、踩到的坑
- **坑 1**: `ip4addr_aton` / `ip4_addr_t` 是 lwip 内部 API, ESP-IDF 5.1 用 `esp_ip4addr_aton` / `esp_ip4_addr_t`
  - 第一次 `pio run` 报 implicit declaration
  - 修: 改用 `esp_ip4addr_aton()`, 但这个函数**只接受一个字符串参数, 返回 `uint32_t`**
  - 第二次 `pio run` 报 "too many arguments"
  - 修: 改用法 `ipinfo.ip.addr = esp_ip4addr_aton("...")`  (直接填 .addr 字段)
- **坑 2**: `stop_provision_httpd()` 在当前实现里没被调用 (AP+STA 共存, 配网页一直开)
  - 编译器 -Werror 升级成 error
  - 修: 加 `__attribute__((unused))` 标记
- **坑 3**: 工具后端 `Shell`/`StrReplace`/`Write` 在 12:30 后全部不可用, 等了 30+ 分钟才恢复
  - 这次所有修复都在工具恢复后做的

### 九、用户操作步骤 (1.4 首次使用)

1. **烧录固件**
   ```bash
   cd /Volumes/Moving/work/01_code/03_Personal/ESP32/esp_balance_robot/1.4
   pio run -t upload
   ```

2. **首次配网** (NVS 没存 WiFi 时)
   - 设备上电后会开热点 `BalanceRobot_Setup_XX` (XX = MAC 后两字节, 密码 `12345678`)
   - 手机连上此热点
   - 浏览器打开 `http://192.168.4.1`
   - 填家里 WiFi 的 SSID 和密码 → 点 "保存并重启"
   - 设备保存 WiFi → 软重启 → 自动 STA 模式连家里 WiFi

3. **验证 OneNet 上线**
   - OneNet 控制台: https://open.iot.10086.cn → 产品 `6YlUqr9lue` → 设备列表
   - 设备 `balancing_dog` 应显示**绿色在线**
   - 设备详情 → 设备调试 → 选 "属性查看", 几秒内应看到 `pitch/roll/motor_l/...` 数据
   - 设备属性上报周期 100ms (在 `user/onenet_client/onenet_client.c` 里的 publish 任务)

4. **App 连接**
   - 打开 OneNet 控制台 → 应用管理 → 创建应用 (Web/小程序/APP)
   - 在 App 里填 Project ID / Product ID / Device Name / AccessKey
   - 通过 OneNet HTTP API (走设备 AccessKey 算 token) 发命令

5. **重新配网**
   - 屏上 K4 → 选 "5. Network" → 按 K4 → 设备清 NVS 重启 → 回到步骤 2

### 十、已知风险
- 配网页 HTTP 服务**没关闭** (AP+STA 共存时配网页一直开, 占用 80 端口)
  - 当前 OneNet MQTT 走 1883, 不冲突
  - 后续要做 "AP 完全关闭" 再调 `stop_provision_httpd()`
- AP 热点开时 2.4GHz 频段会被占用, **家里 WiFi 必须是 2.4GHz** (ESP32 不支持 5GHz)
- 配网页无密码保护 (但 AP 配 WPA2-PSK 12345678, 只能近场使用)
