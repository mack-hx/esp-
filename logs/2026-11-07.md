## 16:00 舵机配平 Zero Point 采样不对称 - Roll/Pitch 两通道对齐

### 问题诊断
**用户识别的根因**：配平采样时，两个轴的采样路径不对称
- **Pitch**：采原始值 (`s_pitch_corr = euler.pitch - comp`) → 存储为零点 → 显示时减零点 ✓ 对称
- **Roll**：采已减零点的值 (`servo_get_roll_angle()` = `euler.roll - old_zero`) → 存储为新零点 ✗ 非对称

**循环抵消现象**：
```
第一次配平：
  new_zero = (raw_roll - old_zero)
  next_display = raw_roll - new_zero = old_zero ≈ 0
  → Roll 显示跳回配平前原始角度，"似乎没配平"
  
Pitch 正常是因为它两路对称
```

### 修复方案
新增 `s_roll_corr` 存储原始 roll 值（未扣零点），与 Pitch 对称

**改动**：`0.45/main_car/user/control/balance.c` 和 `0.45/sub_car/user/control/balance.c`

1. **行 134**：加变量
   ```c
   static float s_roll_corr = 0.0f;  /* 原始 roll，配平采样要用 */
   ```

2. **行 320**：在舵机驱动前保存原始值
   ```c
   s_roll_corr = euler.roll;                   /* 配平采样用 (未扣零点) */
   servo_set_roll_angle(s_roll_corr - s_roll_zero);
   ```

3. **行 830**：配平采样改成读原始值
   ```c
   s_calib_sum_r += s_roll_corr;  /* 改成读原始值，不是 servo_get_roll_angle() */
   ```

4. **行 825**：更新注释
   ```c
   /**
    * @brief 配平采样: 采 CALIB_SAMPLES 个 pitch + roll 取平均
    * @note  采样的是**未扣零点**的 pitch (s_pitch_corr) 和 roll (s_roll_corr),
    *        保证两个通道对称。
    */
   ```

## 15:50 动态互补滤波权重 - 快速纠偏陀螺零偏漂移

### 问题诊断
- **症状**：即使降低 alpha 到 0.98，角度还是跟不上变化（陀螺零偏漂移持续）
- **根本原因**：互补滤波权重是**固定值**，无法应对两个矛盾需求
  - 运动时：需要高陀螺权重（99% +），快速响应、不平滑
  - 静止时：需要高加速权重（99% +），才能纠偏陀螺零偏

### 修复原理（动态权重策略）
根据**角速度幅度**动态调整陀螺/加速权重：
```
|gyro| < 1°/s   → alpha=0.90（陀螺 90% + 加速 10%）← 静止时加速权重强
1°/s < |gyro| < 20°/s  → 线性过渡
|gyro| > 20°/s  → alpha=0.98（陀螺 98% + 加速 2%）← 运动时快响应
```

**效果**：
- 运动中：陀螺主导，响应快、不振荡
- 停下来：加速度大权重，快速纠偏零偏漂移
- 过渡平滑：避免权重切换突跳

### 修改
**文件**：`hardware/mpu9250/mpu9250.c` → `mpu9250_fuse_euler()` 函数

```c
// 新增：根据角速度幅度动态计算融合权重
float gyro_mag = fabsf(data->gyro.x);
float alpha_dyn = 0.90f;
if (gyro_mag > 20.0f) {
    alpha_dyn = 0.98f;
} else if (gyro_mag > 1.0f) {
    alpha_dyn = 0.90f + 0.08f * (gyro_mag - 1.0f) / 19.0f;  // 线性过渡
}

current_angle.pitch = alpha_dyn * current_angle.pitch + (1 - alpha_dyn) * accel_pitch;
```

### 验证
- ✓ 编译成功
- ✓ 副车同步
- Flash 33%、RAM 32.7%

## 15:30 复合倾斜时俯仰角乱的根本修复 - 加速度计 3D 分解

### 问题诊断
- **症状**：车身同时前后+左右倾斜时，俯仰角读数大幅跳动，平衡环发散（"一乱就狂传"）
- **根本原因**：互补滤波的 **atan2(ay, az) 分解在复合倾斜时互相干扰**
  - 当存在 roll 时，Y 轴加速度的重力投影改变
  - 简单的二轴 atan2 没考虑这个耦合
  - 导致 pitch 计算错误

### 修复原理（欧拉角反解）
加速度向量重力分量（精确）：
```
[g·sin(roll)·cos(pitch), -g·sin(pitch), g·cos(roll)·cos(pitch)]
```

**改为**：
```
roll  = atan2(ax, az)
pitch = atan2(-ay, √(ax²+az²))  ← 关键：用 XZ 平面幅度消除 roll 影响
```

**为什么对**：
- √(ax²+az²) 是重力在 XZ 平面投影（纯粹的坡度信号，不受 roll 污染）
- -ay 是重力在 Y 轴分量（纯俯仰信号）
- 两者的 atan2 就是真实 pitch

### 修改
**文件**：`hardware/mpu9250/mpu9250.c` → `mpu9250_fuse_euler()` 函数

```c
// 旧（错）：两个独立 atan2 互相干扰
float accel_pitch = atan2f(data->accel.y, data->accel.z) * 180.0f / M_PI;
float accel_roll  = atan2f(data->accel.x, data->accel.z) * 180.0f / M_PI;

// 新（对）：3D 正确分解
float a_mag = sqrtf(data->accel.x * data->accel.x + data->accel.z * data->accel.z);
float accel_roll  = atan2f(data->accel.x, data->accel.z) * 180.0f / M_PI;
float accel_pitch = atan2f(-data->accel.y, a_mag) * 180.0f / M_PI - PITCH_ZERO_REF;
```
