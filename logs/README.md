# 开发日志

本文件夹用于记录项目开发过程中的重要操作和决策。

## 日志保留策略（2026-10-27 起）

- **本地只保留最近 3 天**的 `YYYY-MM-DD.md`（当前保留：10-25 / 10-26 / 10-27）
- 超过 3 天的日志**先推送到 GitHub 再从本地删除**，内容仍在 git 历史里，需要时可取回
- 日常读日志**只看最近 1~2 天**；更早的需要时由用户指定日期再取
- 清理命令：`scripts/log_prune.sh`（默认保留 3 天，`--dry-run` 可先看）
- 版本级变更说明在 `releases/RELEASE_NOTES.md`

## ⚠ 版本编号对照 (2026-10-21 调整)

项目还没正式实现，版本号**不使用 1 以上的数字**，全部缩小 10 倍：

| 旧编号 | 新编号 |
|---|---|
| 0.1 / 0.2 | 0.01 / 0.02 |
| 1.0 ~ 1.7 | 0.1 ~ 0.17 |
| 2.0 | 0.2 |

- `change_log.txt`（版本级流水）**已按新编号改写**，标题里标注了原编号
- **按日期的日记文件保持原样**：那些是当时的实录，当时目录确实叫 `1.3`；
  而且日记里混着测量值（`1.500°` / `1.25µs` / `1.98°`），批量替换会把数字改错
- 需要按新编号理解某天的记录时，对照上表即可

## 日志格式

每个日志条目应包含：
- **日期时间**：操作发生的时间
- **操作内容**：具体进行了什么修改
- **遇到的问题**：开发过程中遇到的困难
- **解决方案**：如何解决问题的
- **备注**：其他需要记录的信息

## 日志文件命名

按日期命名：`YYYY-MM-DD.md`

例如：`2026-09-30.md`
