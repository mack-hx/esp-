## TFT 字符行循环错位修复

**时间**：2026-10-03 17:09

**问题**：
用户报告 USE_HORIZONTAL=1 模式下字符字面正常，但行的 y 顺序错位。
具体表现为：原本应按 y=1, 14, 24, 36, 60, 72, 100, 112, 140, 150 顺序显示，
实际显示为 "9,10,11,12,13,14,1,2,3,4,5,6,7,8" 循环规律。
- USE_H=2/3 横屏时显示方向正常（MV=1 适配屏幕物理方向）
- USE_H=0 完全颠倒
- USE_H=1 字符字面正常，但多行 y 位置错位

**根因**：
`ui_draw_char` 原实现中按行 8 次循环调用 `tft_write_data(line_data, 12)`，每次只发送 6 像素。
ST7735 模组在两次 RAMWR 数据发送之间，Y 计数器在某些情况下未按预期自动 +1，
导致写入的 6 像素数据被错误地映射到了非预期的物理行位置。

**解决方案**：
将 `ui_draw_char` 改为一次性发送整个 6×8 = 48 像素数据块（96 字节）：
1. 设置 CASET=[x, x+5], RASET=[y, y+7] 后
3. 一次 tft_write_data 发送所有 48 像素

这样 ST7735 内部 X 计数器从 x 推到 x+5 后自动回卷，Y 自动 +1，连续 8 次正常推进，
避免分次发送时某些模组 Y 计数器异常导致的位置偏移。

**修改文件**：
- `0.1/hardware/lcd_ui/lcd_ui.c` - `ui_draw_char` 改为一次发送完整像素块
- `0.1/hardware/tft_display/tft_display.h` - USE_HORIZONTAL 固定为 1

**验证**：`pio run` 编译成功，`pio run --target upload` 烧录成功

## 字模方向 + 行 y 错位修复（第二轮）

**时间**：2026-10-03 17:26

**问题**：
用户上电查看后发现屏幕内容整体排列错位，字符字面方向反（上下颠倒）。
具体表现为 y=1 的 ESP BALANCE 标题出现在屏中央靠下，y=100 的 [K1] Menu 出现在屏顶部。

**根因**：
排查 ST7735S 资料 + 代码后找到两个独立 bug：

1. **字模读取方向反** — `font6x8.h` 中字模定义 bit7=行 1（顶部）, bit0=行 8（底部）。
   原 `ui_draw_char` 用 `((font[col] >> row) & 0x01)`，row=0 取 bit0 = 第 8 行数据，
   写到屏 row=0（顶部），导致字符**垂直翻转**。
2. **行 y 错位** — ST7735S 模组的 RAMWR 自动换行行为异常，
   在 `ui_draw_char` / `ui_fill_rect` / `ui_draw_hline` / `ui_draw_vline` / `tft_clear`
   多次连续调用时，Y 计数器位置不可靠。
   改为每行重新设置 CASET/RASET，避开自动换行。

**解决方案**：
- `ui_draw_char` 中字模读取改为 `((font[col] >> (UI_FONT_H - 1 - row)) & 0x01)`：
  row=0 取 bit7（字模第 1 行 = 顶部），写到屏 row=0（顶部）。
- 所有绘图函数（`ui_draw_char`/`ui_fill_rect`/`ui_draw_hline`/`ui_draw_vline`/`tft_clear`）
  改为**每行单独设置 CASET/RASET**，100% 由 ST7735 命令明确指定写入位置，
  不依赖 ST7735 内部 Y 自动推进。

**修改文件**：
- `0.1/hardware/lcd_ui/lcd_ui.c` - `ui_draw_char` 修正字模方向 + 每行 tft_set_window
- `0.1/hardware/lcd_ui/lcd_ui.c` - `ui_fill_rect` 每行 tft_set_window
- `0.1/hardware/lcd_ui/lcd_ui.c` - `ui_draw_hline`/`ui_draw_vline` 每行 tft_set_window
- `0.1/hardware/tft_display/tft_display.c` - `tft_clear` 每行 tft_set_window

**验证**：
- pio run 编译成功
- pio run --target upload 烧录成功

-#define MOTOR_A_CHANNEL     LEDC_CHANNEL_2

motor.h 一处；改 servo 通道会牵涉到 servo 编号等其他位置，改动大。

## SERVO 2 反向 + 活动范围限幅 30-100°

**时间**：2026-10-03 18:35

2. 两个舵机的活动范围太大，机械结构会卡，需要限制在 30-100°

**修改**：`0.1/user/ui/ui_servo.c`

1. 加逻辑角度范围宏：
```c
#define SERVO_LOGIC_MIN  30
#define SERVO_LOGIC_MAX  100
```

2. `apply_angle(idx)` 加 SERVO_2 反向映射：
```c
static void apply_angle(uint8_t idx)
{
    uint8_t hw_angle;
    if (idx == 1) {
        // SERVO_2 反向: 机械对称
        hw_angle = (uint8_t)(SERVO_LOGIC_MAX + SERVO_LOGIC_MIN - s_angle[idx]);
    } else {
        hw_angle = s_angle[idx];
    }
    servo_set_angle((servo_id_t)idx, hw_angle);
}
```
映射关系：
- 逻辑 30° → SERVO_2 实际 100° (30+100-30=100)
- 逻辑 100° → SERVO_2 实际 30°
- 逻辑 65° (中点) → SERVO_2 实际 65° (反转中心)
- 注意: 反转后 SERVO_2 实际活动范围是 30-100° (跟逻辑范围一致, 但方向相反)

3. `page_key()` K3/K4 限幅改用新宏：
```c
// K3 上限 SERVO_LOGIC_MAX (= 100)
if (s_angle[s_cur_servo] <= SERVO_LOGIC_MAX - 5) { ... } else { s_angle = SERVO_LOGIC_MAX; }
// K4 下限 SERVO_LOGIC_MIN (= 30)
if (s_angle[s_cur_servo] >= SERVO_LOGIC_MIN + 5) { ... } else { s_angle = SERVO_LOGIC_MIN; }
```

4. `ui_servo_draw_one()` 进度条也按 30-100 范围计算：
```c
uint8_t bar_w = (uint8_t)((uint16_t)(s_angle[idx] - SERVO_LOGIC_MIN)
                          * 124 / (SERVO_LOGIC_MAX - SERVO_LOGIC_MIN));
```
这样进度条从 30° 满 0、100° 满 124，视觉上跟限幅范围一致。

## SERVO 页退出不再释放舵机 (保持扭矩)

**时间**：2026-10-03 18:55

**背景**：
用户反馈"从舵机页退出, 舵机 2 就没有力了"。

**原因**：
`page_exit()` 里调了 `servo_release(SERVO_1)` / `servo_release(SERVO_2)`,
`servo_release()` 内部调 `ledc_stop()` 完全停止 PWM 输出,
舵机失去驱动信号 → 扭矩归零 → 靠重力回自由位。

注: 两个舵机都受影响, 只是 SERVO_2 机械受力更明显。

**修改**：`0.1/user/ui/ui_servo.c` `page_exit()` 注释说明 + 删除释放调用：
```c
static void page_exit(void)
{
    ESP_LOGI(TAG, "SERVO page_exit: angle=[%u,%u]",
             (unsigned)s_angle[0], (unsigned)s_angle[1]);
    // 不调用 servo_release(): 保留 PWM 输出, 让舵机保持扭矩停留在当前角度
    // (舵机自然不会松)
    // 注: 上电默认角度由 SERVO_DEFAULT_ANGLE 在 servo_init 中归位
}
```

**未改动**：
- `servo.h/c` 不动 (release 函数保留, 驱动层完整)
- `page_enter()` 不动 (仍是同步软件状态到硬件)
- K3/K4/限幅/反向公式不动
