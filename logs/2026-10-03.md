## TFT 字符行循环错位修复

**时间**：2026-10-03 17:09

**问题**：
用户报告 USE_HORIZONTAL=1 模式下字符字面正常，但行的 y 顺序错位。
具体表现为：原本应按 y=1, 14, 24, 36, 60, 72, 100, 112, 140, 150 顺序显示，
实际显示为 "9,10,11,12,13,14,1,2,3,4,5,6,7,8" 循环规律。
- USE_H=2/3 横屏时显示方向正常（MV=1 适配屏幕物理方向）
- USE_H=0 完全颠倒
- USE_H=1 字符字面正常，但多行 y 位置错位

**根因**：
`ui_draw_char` 原实现中按行 8 次循环调用 `tft_write_data(line_data, 12)`，每次只发送 6 像素。
ST7735 模组在两次 RAMWR 数据发送之间，Y 计数器在某些情况下未按预期自动 +1，
导致写入的 6 像素数据被错误地映射到了非预期的物理行位置。

**解决方案**：
将 `ui_draw_char` 改为一次性发送整个 6×8 = 48 像素数据块（96 字节）：
1. 设置 CASET=[x, x+5], RASET=[y, y+7] 后
3. 一次 tft_write_data 发送所有 48 像素

这样 ST7735 内部 X 计数器从 x 推到 x+5 后自动回卷，Y 自动 +1，连续 8 次正常推进，
避免分次发送时某些模组 Y 计数器异常导致的位置偏移。

**修改文件**：
- `0.1/hardware/lcd_ui/lcd_ui.c` - `ui_draw_char` 改为一次发送完整像素块
- `0.1/hardware/tft_display/tft_display.h` - USE_HORIZONTAL 固定为 1

**验证**：`pio run` 编译成功，`pio run --target upload` 烧录成功

## 字模方向 + 行 y 错位修复（第二轮）

**时间**：2026-10-03 17:26

**问题**：
用户上电查看后发现屏幕内容整体排列错位，字符字面方向反（上下颠倒）。
具体表现为 y=1 的 ESP BALANCE 标题出现在屏中央靠下，y=100 的 [K1] Menu 出现在屏顶部。

**根因**：
排查 ST7735S 资料 + 代码后找到两个独立 bug：

1. **字模读取方向反** — `font6x8.h` 中字模定义 bit7=行 1（顶部）, bit0=行 8（底部）。
   原 `ui_draw_char` 用 `((font[col] >> row) & 0x01)`，row=0 取 bit0 = 第 8 行数据，
   写到屏 row=0（顶部），导致字符**垂直翻转**。

2. **行 y 错位** — ST7735S 模组的 RAMWR 自动换行行为异常，
   在 `ui_draw_char` / `ui_fill_rect` / `ui_draw_hline` / `ui_draw_vline` / `tft_clear`
   多次连续调用时，Y 计数器位置不可靠。
   改为每行重新设置 CASET/RASET，避开自动换行。

**解决方案**：
- `ui_draw_char` 中字模读取改为 `((font[col] >> (UI_FONT_H - 1 - row)) & 0x01)`：
  row=0 取 bit7（字模第 1 行 = 顶部），写到屏 row=0（顶部）。
- 所有绘图函数（`ui_draw_char`/`ui_fill_rect`/`ui_draw_hline`/`ui_draw_vline`/`tft_clear`）
  改为**每行单独设置 CASET/RASET**，100% 由 ST7735 命令明确指定写入位置，
  不依赖 ST7735 内部 Y 自动推进。

**修改文件**：
- `0.1/hardware/lcd_ui/lcd_ui.c` - `ui_draw_char` 修正字模方向 + 每行 tft_set_window
- `0.1/hardware/lcd_ui/lcd_ui.c` - `ui_fill_rect` 每行 tft_set_window
- `0.1/hardware/lcd_ui/lcd_ui.c` - `ui_draw_hline`/`ui_draw_vline` 每行 tft_set_window
- `0.1/hardware/tft_display/tft_display.c` - `tft_clear` 每行 tft_set_window

**验证**：
- pio run 编译成功
- pio run --target upload 烧录成功

## 菜单目录添加主页 + SERVO 频率冲突最终修复

**时间**：2026-10-03 19:10

**用户任务**：
1. 根据 10.2 日志修复舵机频率问题
2. 在目录（菜单）里添加主页选项

### 问题1 根因（与 10.2 日志一致）

`main.c` 初始化顺序：`tft → servo → motor`

| 模块 | TIMER | CHANNEL | GPIO |
|------|-------|---------|------|
| TFT_BLK | TIMER_0 | CH_0 | 12 |
| SERVO_1 | TIMER_1 | **CH_2** | 13 |
| SERVO_2 | TIMER_1 | **CH_3** | 14 |
| MOTOR_A | TIMER_2 | **CH_2** ⚠️ | 15 |
| MOTOR_B | TIMER_2 | **CH_3** ⚠️ | 16 |

`servo_init()` 先把 CH_2/CH_3 绑到 GPIO 13/14（TIMER_1 = 50Hz）
`motor_driver_init()` 紧接着把 CH_2/CH_3 **重新绑定**到 GPIO 15/16（TIMER_2 = 20kHz）
→ CH_2/CH_3 的物理输出引脚此时变成 15/16
→ SERVO GPIO 13/14 失去 LEDC 输出 → 舵机不转

注：10.2 日志记录了此根因，但实际代码未应用改动。本任务正式修复。

### 修复1

`0.1/hardware/motor_driver/motor_driver.h`
```diff
-#define MOTOR_A_CHANNEL     LEDC_CHANNEL_2
-#define MOTOR_B_CHANNEL     LEDC_CHANNEL_3
+#define MOTOR_A_CHANNEL     LEDC_CHANNEL_4
+#define MOTOR_B_CHANNEL     LEDC_CHANNEL_5
```

并在注释中明确 SERVO 和 MOTOR 通道不能重叠的警告。

### 修改3 - 菜单目录加主页

`0.1/user/ui/ui_menu.c`
- `menu_items` 最前面加 `{ (ui_page_id_t)-1, "0. Back to Home" }`
- `MENU_ID_BACK_HOME = (ui_page_id_t)-1` 作为特殊标识
- `page_key(K1)`：选中 BACK_HOME 时直接 `lcd_ui_switch_to(UI_PAGE_HOME)`
  （不能用 `lcd_ui_switch_to((ui_page_id_t)-1)`，会被 `lcd_ui_switch_to` 内部的
   `id >= UI_PAGE_MAX` 校验判 INVALID_ARG 拒绝）
- 默认 `s_selected = 0` 现在指向"Back to Home"，避免一不小心按 K1 进 SERVO

## 舵机统一参数：镜像 + 限位 30-100 + 跨页保持运行

**时间**：2026-10-03 19:30

**用户需求**：
1. 舵机2 与舵机1 镜像 (90° 中心对称)
2. 共同限位 30-100°，默认 80°
3. 任何页面下舵机保持上运行，跨页不跳变/不失力，统一参数

**架构调整**：
舵机 API 改为"逻辑角度唯一 + 物理镜像 + 后台保持"三件套：

| 模块 | 修改 |
|------|------|
| `servo.h` | 新增 `SERVO_LIMIT_MIN/MAX`、`SERVO_DEFAULT_ANGLE=80`、`SERVO2_MIRROR_AT=90`、`SERVO_KEEP_ALIVE_MS=50`；删除 `servo_set_angle`/`servo_release`；新增 `servo_set_target_angle`、`servo_get_target_angle`、`servo_apply_both`、`servo_keep_alive_start` |
| `servo.c` | 内部 `s_target_angle` 维护唯一逻辑角度；`servo_apply_both()` 按 `servo_id_to_phys_angle` 写两路硬件 (舵机1=逻辑, 舵机2=180-逻辑)；后台任务 `servo_keep_alive_task` 每 50ms 调 `servo_apply_both` 防止失力/跳变 |
| `main.c` | `servo_init()` 后调 `servo_keep_alive_start()` 启动后台任务 |
| `ui_servo.c` | UI 只调 `servo_set_target_angle`（限位由 servo.c 处理）；K3 +5° / K2 -5°；K1 退页**不** release；页内同时显示"逻辑角度"+"S1 物理"+"S2 物理 (镜像)"，调试可见 |

**镜像确认（用户选择 ui_limit_phys_mirror）**：
- UI 限位 30-100（逻辑角度）
- 舵机2 物理 = 180 - 逻辑（可能超出 100°，按需求是允许的）
- 例：逻辑 80° → 舵机1 物理 80°，舵机2 物理 100°

**关键设计**：
- 后台任务优先级 5，stack 2048
- `servo_set_target_angle` 同时 (a) clamp 到限位 (b) 立即 apply (c) 写 `s_target_angle`
- 后台任务每 50ms 重新 `servo_apply_both()` → 即使其他模块不小心动了硬件，下个周期就拉回正确角度
- UI 切页 (`on_exit`) 不做任何硬件操作，舵机由后台任务保持

**编译验证**：
- `pio run` → SUCCESS (5.38s)
- 0 错误 0 警告
- RAM: 4.4% (14,276 / 327,680)
- Flash: 30.7% (321,761 / 1,048,576)

**待验证（用户烧录后）**：
- 上电默认逻辑 80°，舵机1 转 80°，舵机2 转 100° (镜像)
- SERVO 页 K3 +5° 多次，舵机1 +5°，舵机2 -5° (镜像)
- 切到其他页（如 ENCODER），舵机持续运行、角度不变
