## 新增：1.3/app uniapp 项目（配套 App 前端）

### 一、目的

ESP32 平衡机械狗到现在只有**网页调参**（WiFi AP + HTTP 调参页面），
操控只能靠车上小屏的 4 个按键，体验很差。

加一个**手机/小程序**的遥控 App 是大趋势：
- 远程看姿态/电池（不用蹲车旁边看小屏）
- 滑块调参（手机屏幕大，比网页好操作）
- 前进/后退/急停（手柄式控制）

按用户选型：
- **平台**：uniapp 全端发行（H5 + 小程序 + iOS/Android）
- **通信**：MQTT（走公共 broker，先打通流程）
- **位置**：放到 `1.3/app/`（不另开 Git 仓库，跟 1.3 同走一个版本号）

### 二、范围控制

**只做 App 前端**。ESP32 端的 MQTT 客户端**这次没做**（`user/mqtt_client/mqtt_client.c/h`）。

理由：
- 1.3 已经处于"待真机试车"状态，方向/参数都没真车验证
- App 前端做完，先在 H5 上能跑、能连 EMQX 公共服、能发/收消息
- 验证通过后，再写 ESP32 端 MQTT 客户端时，把 `app/common/topic.js` 1:1 翻译成 C 字符串即可
- 两边一起改容易混，**分步做可控**

> sdkconfig 里 `CONFIG_MQTT_PROTOCOL_311=y` 已经在编译里（esp-mqtt 库已链接），
> 缺的就是业务侧 mqtt_client.c/h。这次没补，留到 1.4 或 2.0。

### 四、关键设计

#### 1. MQTT 客户端封装 (`utils/mqtt.js`)

- **单例**：全局一个连接，切换设备时复用
- **状态机**：`idle | connecting | connected | disconnected | error`
- **状态广播**：`onState(cb)` 订阅，state 变化时通知所有 cb
- **topic 注册表**：`subscribe(topic, cb)` 同 topic 多 cb，**只在第一次注册时真去订阅**，
  全部 cb 退订后才 unsubscribe
- **自动重连**：依赖 mqtt.js 自带的 `reconnectPeriod: 5000`
- **断线区分**：主动 disconnect 时 state 标 `disconnected`，被动断线时 `close` 事件触发也标 disconnected

#### 2. 控制指令封装 (`utils/control.js`)

- **持续 publish**：`startMove(dir, speed)` 后 50ms 周期 publish `{vx, vy, w}`，
  触摸松开 `stopMove()` 立即归零 + 停心跳
- **为什么 50ms**：20Hz 远超人手反应 (~150ms)，同时不占 broker 带宽
- **qos=0**：cmd/move 不需要确认，丢一帧无所谓（下一帧马上到）
- **qos=1**：急停/起立/配平/参数读写，重要指令

#### 3. Topic 命名规范 (`common/topic.js`)

```
esp32/{deviceId}/cmd/move         App → ESP32   {vx, vy, w}  20Hz
esp32/{deviceId}/cmd/stop         App → ESP32   急停
esp32/{deviceId}/cmd/stand        App → ESP32   起立
esp32/{deviceId}/cmd/calibrate    App → ESP32   配平

esp32/{deviceId}/state/pose       ESP32 → App   姿态
esp32/{deviceId}/state/motor      ESP32 → App   电机
esp32/{deviceId}/state/battery    ESP32 → App   电池
esp32/{deviceId}/state/heartbeat  ESP32 → App   心跳

esp32/{deviceId}/param/get        App → ESP32
esp32/{deviceId}/param/set        App → ESP32
esp32/{deviceId}/param/resp       ESP32 → App

esp32/{deviceId}/ack              ESP32 → App
```

**写 ESP32 端 mqtt_client.c 时，必须 1:1 复制这套字符串**。

#### 4. 参数表镜像 (`common/paramDef.js`)

- 16 项，跟 1.3 PARAM_DATA_VERSION=7 一致
- 改了 `param.c` 就要同步这个文件，否则 App 滑块范围跟车端对不上
- 表格里用 `key` 字段 (`bal_kp` / `spd_kp` ...) 做 JSON 传输 key，
  跟 ESP32 端 `g_param_items` 里的 `key` 严格一致

#### 5. tabBar 图标

`pages.json` 里**故意没配 iconPath**，走纯文字 tabBar。
原因：tabBar 要 6 张 81x81 PNG，目前手头没有，先让项目能跑。
等真要发布再补图标。

## 修复：HBuilderX 跑 H5 报错 "缺少 index.html" + "Failed to resolve mqtt/dist/mqtt.min.js"

### 问题

装好 HBuilderX App 开发版后点运行，浏览器 overlay 报两条错：

1. `请确认您的项目模板是否支持vue3：根目录缺少 index.html`
2. `Failed to resolve import "mqtt/dist/mqtt.min.js" from utils/mqtt.js`

### 原因

- 第 1 个：HBuilderX 启动 dev server 时，uniapp 的 Vite 插件需要 `index.html` 入口模板，原模板没放这个文件（cli 模式默认依赖包里有，但被 HBuilderX 内部节点覆盖了）
- 第 2 个：`utils/mqtt.js` 之前写 `import mqtt from 'mqtt/dist/mqtt.min.js'`，是想绕过 webpack tree-shaking 直接用 minify 版，但 HBuilderX 的 Vite import-analysis 走包 `exports` 字段，不认穿透 `dist/*.min.js` 这种内部路径

### 修复

1. `app/index.html` 新建：标准 H5 入口模板，body 里挂 `<div id="app">` 和 `<script src="/main.js">`
2. `app/utils/mqtt.js:17` 改成 `import mqtt from 'mqtt'`（走包默认导出，Vite 自动 tree-shake 选 min 版）
3. `app/package.json` 补 `devDependencies`：`@dcloudio/uni-cli-shared / uni-h5 / uni-stacktracey / vite-plugin-uni / uni-automator / types` + `vite@^5.2.8`
   - 加 `scripts: { "dev:h5": "uni", "build:h5": "uni build" }`
4. `npm install --legacy-peer-deps`（uni-h5 老版本 peer 写的是 vite@2，必须 legacy）

### 验证

HBuilderX 里点运行，浏览器打开 `http://localhost:8080`，4 个 tab 都能进。
