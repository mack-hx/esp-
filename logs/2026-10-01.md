## SK6812 时序问题结论与 Q0 开关版实现

**时间**：2026-10-01 13:30

**背景**：
SK6812 DIN 接 74HC595 Q0，按文档要求本应使用 RMT 外设生成精确时序。
但项目当前无多余 GPIO 可飞线到 SK6812，需评估能否"仅用 Q0 模拟"。

**问题分析**（已查阅 Nexperia / TI / Onsemi 数据手册）：

74HC595 内部有两套独立寄存器：
- **移位寄存器 (Shift Register)**：每个 SCLK 上升沿移入 1 bit
- **存储寄存器 (Storage Register)**：只有 RCLK 上升沿时，移位寄存器内容才**拷贝**到存储寄存器，并更新到 Q0~Q7 输出

**关键事实**：
- RCLK 触发后，Q0 被锁存为某个固定值，并**保持稳定**
- 不触发 RCLK 时，Q0 维持上一次锁存状态，**完全不动**
- SK6812 要求 1 bit 周期 1.25µs 内产生 T0H/T0L 或 T1H/T1L 的高低翻转
- 74HC595 在 1.25µs 内无论怎样操作 SCLK/RCLK，都只能让 Q0 跳变 1 次（不锁存不变 / 锁存后只跳一次）

**结论**：**单纯依靠 74HC595 Q0 物理上无法产生 SK6812 归零码时序**。

**尝试过的方案与可行性**：
| 方案 | 结论 |
|------|------|
| 软模拟 (esp_rom_delay_us(1)) | 1.25µs 内翻转不了 ❌ |
| SPI 硬件外设驱动 HC595 (5MHz) | Rclk 不触发则 Q0 不动 ❌ |
| LEDC PWM 直驱 | Q0 是 HC595 输出稳态，LEDC 无法控制 ❌ |
| Q0~Q7 编码预设色 | SK6812 收到稳态电平，行为是"保持上次颜色" ❌ |

**最终方案**（用户认可）：Q0 开关版 + 颜色亮度缓存

**修改文件**：
- `0.1/hardware/led/led.h` — 重新设计接口
  - 增加 `led_preset_t` 预设颜色枚举（8 种）
  - 增加 `led_set_preset()` / `led_set_brightness()` / `led_get_on()` / `led_get_color()` 函数
  - `led_color_t` 颜色结构保留，但明确标注"仅逻辑记录"
  - 文件头注释说明硬件限制和未来改线方向

- `0.1/hardware/led/led.c` — 实现开关逻辑
  - `current_color[]` / `current_on[]` 数组记录每颗 LED 的逻辑状态
  - 颜色变化时仅做亮度阈值判断（>0 则点亮 Q0）
  - **仅在状态变化时才触发 RCLK**，避免无谓锁存影响 Q1~Q7 其他引脚
  - 7 种预设颜色映射为开/关状态
  - 启动日志明确告知用户 SK6812 实际只支持开关

**后续建议**（不在本次范围内）：
- 改线：将 SK6812 DIN 改接到 ESP32 任意空闲 GPIO（如 PCF8574 INT 引脚 GPIO21、MPU9250 INT 引脚 GPIO3）
- 软件：用 RMT 外设 + 10 MHz 时钟驱动 SK6812，调色调光即可正常工作
- 或者改用普通 LED（仅开关），放弃 RGB 灯珠

**备注**：
- 本次未触碰 `hc595.c` / `hc595.h`，Q1~Q7 输出行为完全保留
- Q0 现在被 LED 模块独占，但 hc595_set_led() 仍然能正常工作
- 调用方在 `main.c` 中按需使用 `led_set_preset(id, LED_PRESET_GREEN)` 等 API

## TFT 屏幕 ST7735S 初始化序列修复

**问题**：

- TFT 屏幕完全黑屏, **背光也没亮**
- 之前的 `tft_display_init()` 初始化序列严重残缺

**根因分析**：
1. **初始化序列严重残缺** (参考工程用的是完整序列):
   - 缺失 `0xB1/B2/B3` 帧率设置
   - 缺失 `0xB4` Dot inversion
   - 缺失 `0xC0~C5` 电源序列 (POR 后的电压/VCOM 配置)
   - **缺失 `0x36 MADCTL` (扫描方向!)** —— 没有这个, 像素写入位置完全错乱
   - 缺失 `0xE0/E1` Gamma 校正
   - 仅有 `0x01 SWRESET` + `0x11 SLPOUT` + `0x3A COLMOD` + `0x29 DISPON`

2. **命令顺序错误**:
   - 之前: 先 `0x01 SWRESET` 后 `0x11 SLPOUT`
   - 正确顺序: 先 `0x11 SLPOUT` (退出睡眠) 才能接受其他命令
   - `0x01 SWRESET` 不是必须的 (POR 已复位)

3. **背光没亮**:
   - `main.c` 之前调 `tft_set_backlight(80)`, **背光实际应该亮**
   - 怀疑原因: 屏幕被错误配置后整体不响应, 或 GPIO12 接线问题
   - 现已加强为 `tft_set_backlight(100)` 确保点亮

4. **DMA 缓冲区过大**:
   - 之前 `max_transfer_sz = TFT_WIDTH * TFT_HEIGHT * 2 = 40960` 远超默认 DMA 上限
   - 现已改为 `TFT_SCREEN_W * 2 = 256` (一行), 与 `tft_clear()` 的 DMA 调用一致

5. **CASET/RASET 偏移**:
   - 之前 `uint8_t caset[] = {0, 0, 0, TFT_WIDTH - 1}` 直接用 8 位
   - ST7735 协议是 16 位 (高字节先), 之前实现默认高位为 0 没问题
   - 现加入 `TFT_X_OFFSET` / `TFT_Y_OFFSET` 宏, 方便适配不同模组

## LCD UI 系统实现

**时间**：2026-10-01 20:50

**需求**：
设计 LCD 的 UI 界面：分为主页，菜单页，和功能页面，每个 ui 要一个.c 文件，
K1 负责进入菜单页和进入所选页面，在菜单页 K2/K3 负责更换所选页面，
所选页面用箭头指出，上电默认显示主页。先添加几个功能页：

**架构**：
- 单任务轮询：主循环 50ms 扫描按键，每 150ms 调用页面 on_refresh 刷新实时数据

- 状态机：`current_page` 单一变量，`lcd_ui_switch_to()` 处理旧页退出 + 新页进入
- 工具 API（所有页面共享）：字符/字符串/线/矩形/填充/箭头

**遇到的问题与解决方案**：

1. **`on_exit` 函数名与 newlib 冲突**
   - 现象：`error: conflicting types for 'on_exit'; have 'void(void)'`，
     `stdlib.h` 的 `on_exit` 是 `int(void (*)(int, void *), void *)`
   - 解决：所有页面回调函数改名为 `page_enter/page_exit/page_key/page_refresh`
   - typedef 类型名 `ui_page_exit_t` 和 struct 字段名 `on_exit` 不冲突，保留

2. **`esp_read_mac` 未声明**
   - 现象：`ui_wifi_bt.c` 隐式声明
   - 解决：`#include "esp_mac.h"`，并在 `lcd_ui/CMakeLists.txt` 添加 `esp_hw_support` 到 REQUIRES

3. **`TAG` 未使用警告**
   - 解决：所有页面文件 `static const char *TAG = ...` 加 `__attribute__((unused))`
