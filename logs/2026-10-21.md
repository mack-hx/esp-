## macOS CommandLineTools Python posix_spawn 问题修复

**问题描述**：
- macOS 15.x (Darwin 25.6.0) 上，PlatformIO/ESP-IDF 编译时出现 Python `posix_spawn` 错误：
  ```
  python: posix_spawn: /Library/Developer/CommandLineTools/Library/Frameworks/Python3.framework/Versions/3.9/Resources/Python.app/Contents/MacOS/Python: Undefined error: 0
  ```
- 根本原因：系统 `/usr/bin/python3` 的 `sys.prefix` 指向 CommandLineTools 的 Python.framework，但该 Python.app 在被 `posix_spawn` 调用时失败

**解决方案**：
1. 安装 Homebrew Python 3.11
   ```bash
   brew install python@3.11
   ```

2. 修改 PlatformIO 的 Python 路径配置
   - 文件：`/Users/m/Library/Python/3.9/lib/python/site-packages/platformio/proc.py`
   - 修改 `get_pythonexe_path()` 函数，优先使用 Homebrew Python：
   ```python
   def get_pythonexe_path():
       homebrew_python = "/opt/homebrew/opt/python@3.11/bin/python3.11"
       if os.path.isfile(homebrew_python):
           return homebrew_python
       return os.environ.get("PYTHONEXEPATH", os.path.normpath(sys.executable))
   ```

3. 为 Homebrew Python 安装依赖
   ```bash
   /opt/homebrew/opt/python@3.11/bin/python3.11 -m pip install setuptools click platformio
   ```
   - 需要安装旧版本 setuptools (<71) 以获得 pkg_resources 模块

4. PlatformIO 会自动使用 Homebrew Python 创建 ESP-IDF 虚拟环境

## 1.7 版本: App 与小车通信全链路打通 (下午)

### 一、先摸清平台侧的真实情况

用 Python 直连 OneNet 开放接口逐个试, 确认:

| 接口 / 参数 | 结果 |
|---|---|
| `GET /thingmodel/query-device-property` | ✅ code 0, 能读到设备上报的属性 |
| `POST /thingmodel/call-service` | ✅ 不带 `project_id` 也能调 |
| `POST /thingmodel/set-device-desired-property` | ✅ 不带 `project_id` 也能设 |

| 文档里那把 AccessKey | ❌ `10403 invalid authorization` |
| `params: {"vx":0.5}` | ❌ `10412 identifier not exist` |
| `params: {"speed":0.5}` | ✅ code 0, 且**设备能收到** (平台会 push `property/set`) |

结论: **物模型里从来没有 `vx` / `w`**, 之前的移动指令全部被平台拒了, 所以
"App 控不动车"不是 App 的问题, 是指令用了不存在的标识符。

### 二、定位到 4 个真 bug

**Bug 1 (最要命): 服务应答随机丢失**
`onenet_client.c` 的 `handle_service_invoke()` 里:
```c
static char t[160] = {0};
memcpy(t, topic, copy);      /* ← 没有补 '\0' */
```
`t` 是 static 缓冲区, 上一次调用留下的尾巴不会被清掉。
先收到 `param_save`(61 字符) 再收到 `stop`(55 字符) 时, `t` 会变成
`".../stop/invoke"` + 残留的 `"invoke"`, `strrchr` 找出来的是 `"/invokeinvoke"`,
`strcmp != "/invoke"` → **这个服务被直接丢掉, 平台收不到应答就报"设备响应超时"**。
现象非常随机: 第一次调 `stop` 成功, 第二次调 `stand` 就超时。
修: `memcpy` 之后补 `t[copy] = '\0';`

**Bug 2: 属性上报没对齐物模型的 step**
平台一帧里只要有一个属性不符合 step / 超范围, **整帧被拒收**。
`gz` 和 `speed` 的 step 是 0.01, 原来跟 `pitch/roll/yaw` (step 0.1) 混在一帧里、
按 `%.1f` 打印, 属于运气好才没被拒。
修: 拆成两帧 —— 角度帧 (`pitch/roll/yaw`, `%.1f`) + 角速度帧 (`gz`, `%.2f`)。

**Bug 3: 事件参数超上限**
物模型里 `armed.time` 上限 1e9、`fallen.time` 上限 5e8, **单位是秒**;
设备发的是毫秒。`fallen.pitch` 的 step 是 1 (整数), 设备发的是 `-3.3`。
修: 时间改发开机秒数, pitch 取整。

**Bug 4: App 一条指令失败, 整个连接被判成"错误"**
`oneApi.markError()` 被每条指令的 catch 都调了一遍, 于是点一下没建属性的
灯按钮 (平台回 10412), 状态就变成 `error`, 之后连移动指令都发不出去
(提示"请先在连接页配置 OneNet")。
修: 只有**鉴权类**错误 (HTTP 401/403 / code 10403) 才改连接状态,
单条指令失败只弹提示。

### 三、物模型缺的东西 (已整理成清单, 等用户补)

## 1.7 第二轮: 用户补完物模型后的复检 + 收尾 (傍晚)

`GET /thingmodel/query-thing-model?product_id=xxx` 是存在的, 只是 **token 的 `res`

   → 设备改成回空对象 `"data":{}` 适配现在的物模型 (代码里留了注释, 以后给
   `param_set` 补上 `ok` 输出后改一行即可)。
2. **App 的参数表跟设备对不上** (大问题, 见下面第三节)。

### 三、发现并修掉的 3 个 App 侧 bug

**Bug A: App 的参数表跟设备不同步 (危险)**
`app/common/paramDef.js` 声称"1:1 镜像 param.c", 实际有 6 项对不上:

| App 里的 key | 设备真正的 key | 后果 |
|---|---|---|
| `encoder_gear` (默认 30) | `gear` (默认 1.0) | 减速比保存不进去 |
| `motor_db` (默认 5) | `deadzone` (默认 8) | 死区保存不进去 |
| `servo_ctr` (默认 90) | `servo_c` (默认 80) | 舵机中位保存不进去 |
| `arm_pitch` 默认 5 | 默认 8 | 滑块范围/默认值跟车不一致 |
| `arm_rate` 默认 30 | 默认 20 | 同上 |
| `arm_time` 范围 100~5000 步长 50 | 0~3000 步长 100 | 同上 |

后果: App 上"拉取"显示的是默认值 (不是车上的真实值), "保存"时这 3 个参数
根本传不到设备, 但界面照样显示"已保存"。
→ 已按 `user/param/param.c` 的表逐项对齐 (key / 默认值 / 范围 / 步长 / 小数位)。

**Bug B: 状态页里有一份"过期"的 PID 编辑器 (危险)**
`pages/status/status.vue` 里藏着 `bal_kp/bal_ki/bal_kd/vel_kp/turn_kp` 五个滑块,
点"保存参数"会把这一整包发给设备。设备只认 `bal_kp/bal_ki/bal_kd`,
所以**按一下保存, 车的 `bal_ki` 就从 12 变成 0, `bal_kd` 从 2 变成 10**,
而且 `param_save` 会把它写进 NVS 永久生效。
→ 删掉这份重复编辑器, 状态页改成"去调参"按钮跳到参数页 (参数表是唯一入口)。

**Bug C: 浏览器一刷新, App 就"未连接"**
连接状态只存在内存里, 刷新后回到 `idle`, 各页面直接提示"未连接 OneNet",
必须先去连接页手点一次"验证配置"。
→ `App.vue` 的 `onLaunch` 里, 有配置就自动 `ensureReady()` 一次
(真的拉一次设备属性, 通了才算 ready)。刷新后直接就能操作。

### 四、新增: 执行器状态跟车上的真实值对齐

设备现在会主动上报 `led_on/led_color/led_brightness/magnet_on/servo1_angle/servo2_angle`。
App 遥控页原来这些按钮是"自己瞎猜"的状态 (比如电磁铁按钮只知道自己点过几次,
不知道车上的真实状态)。现在遥控页的轮询会拿设备上报的值来纠正界面。

防抖: 记录 App 最近下发的值 + 下发时刻, **刚下发过的 2.5 秒内不用设备值覆盖**,
免得把用户正在拖的滑块弹回去; 超过 2.5 秒且设备值跟 App 下发的值不一样,
才认为是外部 (物理开关/别的会话) 改的, 用设备的值覆盖界面。

### 五、设备端本轮改动

- `param_set` 应答改成空对象 (适配物模型里空的输出声明)
- 新增上报帧: 执行器状态 (灯 + 电磁铁, int 帧) 和舵机角度 (float 帧, step 1), 1s 一帧
- 修 bug: 舵机角度帧的缓冲 `svbody` 只有 128 字节, 拼帧拼不下直接被丢掉
  (平台那边一直收不到 servo1_angle/servo2_angle)。改成 256, 执行器帧 512。

### 五、推送到 GitHub (撞上 push protection)

第一次 `git push` 被 GitHub 拒了:

```
remote: error: GH013: Repository rule violations found for refs/heads/main.
remote:            path: .cursor/rules/github-config.md:10
remote:            path: .cursor/rules/github-config.md:15
```

**原因**: `7ccc8ef` (1.6 那个提交) 往仓库里写进了一把明文 GitHub PAT。
这三个提交 (1.6 / 打通通信 / 清理整理) 都**还没推到远端**, 远端 HEAD (`166313a`)
里根本没有这个文件 —— 所以是 GitHub 的 secret scanning 在拦"要新推上去的内容"。

**解决**: 用 `git filter-branch --index-filter` 把这段历史重写掉,
每个提交里的 token 都替换成 `YOUR_TOKEN_HERE`, 然后清掉 `refs/original/*`

> 远端本来就没有这个 token, 所以只需要普通 push, 不用 force push。

### 七、经验

- **改版本号不是改一个字符串的事**。目录名、版本字段、文档里的路径引用、
  代码注释里的历史版本号, 散在 30 多个地方。漏改一个, 文档就会指向不存在的路径。
  → 改完用 grep 全量扫一遍旧编号, 剩下的必须逐条判断是不是版本号
    (协议版本 / 数据结构版本 / 依赖版本 都不能动)。
- **删旧版本前先想清楚 "历史还在不在"**。删掉目录不等于删掉历史 ——
  git 里每个版本都有提交, 需要回看随时 `git checkout`。
  真正占地方的是没被跟踪的 `.pio` / `node_modules`, 那些才是删空间的重点。
- 打包脚本要**显式排除** `node_modules` / `.pio` / `.cache` / `compile_commands.json`,
  否则压缩包会从几百 KB 变成几十 MB。
- **明文 token 写进仓库 = 已经泄露**, 哪怕后来改掉也一样。
  本地删掉不算完, 远端历史、GitHub 的 secret scanning 都要过一遍,
  最后还得去后台吊销。
- **"删旧版本"和"删 GitHub 上的历史"是两件事**。本地目录是磁盘空间问题,
  可以删; GitHub 上的 release 是项目的历史档案, 删了就找不回来了。
  → 以后执行"清理旧版本"时, 默认只清本地, GitHub 上的 release / tag 一律保留。
- 删之前先确认**能不能恢复**: 本地旧目录删了, 但只要进过 git 就能
  `git archive <tag> <目录>` 取回来重新打包。这次 7 个旧 release 全靠这个救回来的。
- 历史日志里混着测量值 (`1.500°` / `1.25µs` / `1.98°`), **批量替换版本号会把数字改错**。
  → 日记类文件保持原样, 只在 `logs/README.md` 里放一张版本号对照表。
