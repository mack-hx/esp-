## 16:20 坡道保持 + 横滚闭环（对照 WL1 开源轮腿机器人）

### 背景
- 现象：上坡时车身往坡下溜、越溜越快；同时车头偏向一侧斜着冲出去。坡既有俯仰坡也有横向坡。
- 对照 `lk888l/wheeled-legged_Robot-WL1`：它的外环直接对平均轮速做 PI（无位置锚点），横滚用 IMU 角闭环驱动左右腿长差（增量 PID + 3° 以上几何正弦前馈）。
- 本项目原状：位置环是 LQR 比例项，位置积分只在 `|速度|<4 cm/s` 时累积、否则按 0.3 s 衰减；横滚补偿是查表开环且默认关闭、表为空时增益 0，`servo_write_hw()` 里实际已没有补偿代码，等于完全没有横滚稳定。

### 修改
- `user/pid/lqr.c` `lqr_pos_integral()`：新增 `sliding_away`（偏差与速度反向 = 正在远离锚点）判定，溜坡时即使超速也继续累积，不再衰减。
- `user/pid/lqr.h`：`LQR_POS_I_MAX` 5→12°，`LQR_POS_I_BAND` 6→8 cm。
- `user/pid/position_pid.h`：`POS_PID_LEAN_MAX` 8→12°（`pitch_cap` 取 max(7, 它)，自动跟随）。
- `hardware/roll_compensator/`：重写为横滚闭环。`roll_comp_calculate(dt, roll, out)` 用 PD + 弱积分算出左右舵机角度偏置，死区 1°、软过渡 1°、限幅 ±20°、变化率 ≤60°/s、|roll|>35° 视为侧翻并退回 0。
- `hardware/servo/`：新增 `servo_set_roll_trim(left, right)`；`servo_write_hw()` 在逻辑角上叠加该偏置后再做物理映射，`s_angle[]` 仍是用户目标（UI 显示不受影响）。
- `user/control/balance.c`：控制任务每周期（10 ms）按 `s_state == BAL_STATE_BALANCING` 使能补偿，用已扣零点的 `servo_get_roll_angle()` 算偏置并下发。
- 删除 `servo_roll_table.c/.h`（查表开环），`hardware/roll_compensator/CMakeLists.txt` 同步去掉该源文件。

## 19:00 三项实测问题修复 (单边桥 / 上坡 / 走不直)

### 测试结果
- 测试一 单边桥: 架高一边后横滚环把另一边抬起, 车身一平 P 项归零, 腿又收回。
- 测试二 上坡: 平面能站, 上坡爬不动、下坡过快, 平面接坡瞬间稳不住 (要手扶)。
- 测试三 单腿过单边桥: 走不直, 随后一条腿狂转, 摔倒。

### 根因与修改
- **偏航阻尼取错轴 (测试三主因)**: `balance.c` 用 `gyro.z` 当航向角速度, 但车体
  yaw 轴是 MPU 的 Y 轴 (`mpu9250.c` 里 `yaw += gyro.y`), `gyro.z` 是横滚角速度。
  等于把横滚抖动灌进差速环 → 走不直、单侧轮悬空时越拱越快。改为 `gyro.y`。
  同时给阻尼项加死区 10°/s 与限幅 ±4 rpm (`YAW_DAMP_MIN_RATE` / `YAW_DAMP_MAX_RPM`)。
- **横滚环急回弹**: 新增 `roll_comp_reset()`; 积分在死区内按 3 s 泄放 (不锁存,
  坡度变了仍能重新找平衡); 偏置抬起 30°/s、收回 12°/s, 不再"归零瞬间把腿收掉"。
  上限 20→15°, 死区 1→1.5°。
- **横滚积分饱和 (抽风)**: 新增无响应看门狗 —— 输出 >3° 且横滚变化率 <2°/s 持续
  0.6 s, 判定该侧腿没受力, 冻结并泄放积分。
- **配平 roll 不生效**: 采零点前先 `roll_comp_reset()` + `servo_set_roll_trim(0,0)`,
  保证零点采的是"腿在中位时的车身姿态"; 采完再复位一次。
- **上坡慢 / 下坡快**: 速度环倾角上限 7→10° (`SPD_PID_WALK_PITCH_MAX`)。
  新增坡度前馈 `SLOPE_FF_K=0.35`: 行走时把低通 (1.5 s) 后的倾角按比例补进目标,
  上坡多前倾、下坡多后仰, 限幅 ±3°。
- 修 `test_speed_pid_pc.c` 里写死的 7° 断言, 改用宏。

## 19:50 修 roll 配平失效 + 平衡控制页加 Roll/舵机

### 现象
点配平后 Pitch 归零正常, Roll 显示不动, 怎么配都配不平。

### 根因
`balance_calib_step()` 采的 roll 来源是 `servo_get_roll_angle()`, 它已经扣过旧零点;
却把采样均值直接赋给 `s_roll_zero`, 等于:
  新零点 = mean(原始roll − 旧零点) → 新显示 = 原始roll − 新零点 = 旧零点 ≈ 0
每配一次就把 roll 零点抹回 0。pitch 采的是未扣零点的 `s_pitch_corr`, 所以没这个问题。

### 修改
- `balance.c`: `s_roll_zero += mean` (旧零点 + 采样均值), 注释写明两条路的区别。
- `balance.c`: `s_data.roll` 改为已扣零点的值, LCD/TRACE/横滚闭环同源。
- `ui_balance.c`: 新增 Roll 行 (`Rol:`) 和舵机行 (`Svo: 100/100`), 行距 10px 重排。

### 验证
- 编译通过, 已烧录。串口 TRACE 显示 roll 实时变化 (当前 -16.6, 零点为 0)。

## 20:05 平地按方向键猛冲 -> 关闭坡度前馈

### 现象
平地上按前进/后退，车直接猛冲。

### 根因
坡度前馈把"低通后的实际倾角"按 0.35 回灌倾角目标，而倾角本身是平衡环的输出：
倾角偏一点 → 前馈加大目标倾角 → 车更倾 → 前馈继续加大，形成正反馈，
几秒内顶到限幅（前馈 ±3°，目标上限 10°），表现为一按就猛冲。

### 修改
- `SLOPE_FF_K` 0.35 → 0（血肉保留，参数在，需要时再开并观察是否自激）。
- 注释写明倾角回灌目标会自激，倾角上限保持 10°（上坡仍需要更大前倾）。

### 遗留
烧录失败：串口设备 `/dev/cu.usbmodem*` 从系统消失（USB 掉线），待用户重新插线。
