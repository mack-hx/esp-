## 08:50 App 姿态控制模块 (0.43, 已完成)

### 需求
在遥控页面舵机控制模块上方添加姿态控制，包含：
- **蹲下**：舵机角度设为 100°（标准蹲姿）
- **起立**：舵机角度设为 40°（标准站姿）
- **跳舞**：舵机按 1Hz 频率交替 40°↔100°

### 实现 (0.43/app/pages/control/control.vue)
1. **UI 布局**：
   - 在舵机控制区块前新增"姿态控制"卡片
   - 三个按钮：蹲下（橙色）、起立（绿色）、跳舞（蓝色）
   - 跳舞按钮激活时显示"停止"并高亮

2. **功能实现**：
   - `onPoseSquat()`：停止跳舞，设置双舵机到 100°
   - `onPoseStand()`：停止跳舞，设置双舵机到 40°
   - `onPoseDance()`：切换跳舞状态
   - `_startDance()`：启动定时器，每 1s 切换一次姿态
   - `_stopDance()`：清除定时器，停止跳舞
   - `_danceStep()`：执行单次姿态切换 (40°↔100°)

3. **生命周期管理**：
   - `onUnload()`：页面销毁时清除跳舞定时器
   - `onHide()`：页面隐藏时停止跳舞

### 细节
- 跳舞频率：1Hz (每秒切换一次，40°→100°→40°...)
- 跳舞时发送失败不弹错误提示（避免打断动作）
- 点击蹲下/起立会自动停止跳舞
- 跳舞按钮激活时背景变绿色，文字变"停止"

### 待验证
- App 重新打包后验证三个姿态按钮功能
- 跳舞动作是否流畅（1Hz 频率是否合适）
- 舵机响应速度能否跟上 1Hz 切换

## 08:20 横滚角姿态补偿功能 (0.43, 已编译, 待烧录真机验证)

### 需求
用户需要横滚角 (Roll) 姿态补偿应对左右高度不同的地面:
- 现状: 只有俯仰角 (Pitch) 控制, 左右高度差时平衡环误判
- 目标: 根据 Roll 角 + 舵机状态自动调整左右腿长度适应地形
- 姿态定义: ≤70° 为站立态 (标准 40°), >70° 为蹲下态 (标准 100°)
- 补偿方向: 站立时高侧收腿 (角度↑), 蹲下时低侧伸腿 (角度↓)

### 实现 (0.43/main_car)
1. **新增模块** `hardware/roll_compensator/`:
   - `roll_compensator.c/h`: 补偿算法实现
   - 输入: Roll 角 + 两腿当前角度
   - 输出: 左右腿补偿量 (°, 可直接叠加到舵机目标角度)
   - 参数: 增益 `ROLL_GAIN_DEFAULT=1.5`、死区 `ROLL_DEADZONE=2.0°`、限幅 `ROLL_COMP_MAX=25°`

2. **修改 `servo.c`**:
   - 新增状态缓存 `s_roll_angle` (当前 Roll 角)
   - `servo_write_hw_ex()`: 在实际输出前叠加 Roll 补偿
   - `servo_set_roll_angle()`: 供外部更新 Roll 数据
   - `servo_init()`: 初始化 Roll 补偿器

3. **修改 `balance.c`**:
   - `balance_read_sensors()`: 每周期从 MPU9250 读 Roll 角, 调用 `servo_set_roll_angle()` 更新到舵机模块

4. **编译系统**:
   - `CMakeLists.txt`: 注册 `roll_compensator` 组件路径
   - `main/CMakeLists.txt`: 添加 `roll_compensator` 依赖
   - `servo/CMakeLists.txt`: 添加 `roll_compensator` 依赖

### 补偿策略
```
Roll 角正负约定 (待 MPU 实测确认, 暂假设):
  roll_deg > 0: 右侧高 (左倾)
  roll_deg < 0: 左侧高 (右倾)

站立态 (≤70°): 高侧收腿 (角度↑)
  roll > 0 (右高): right_comp = +|roll|*gain, left_comp = 0
  roll < 0 (左高): left_comp = +|roll|*gain, right_comp = 0

蹲下态 (>70°): 低侧伸腿 (角度↓)
  roll > 0 (右高左低): left_comp = -|roll|*gain, right_comp = 0
  roll < 0 (左高右低): right_comp = -|roll|*gain, left_comp = 0
```

### 编译结果
- **编译**: 成功 (RAM 30.9%, Flash 32.0%)
- **固件**: `.pio/build/esp32-s3-devkitc-1/firmware.bin` 已生成

### 待验证 (真机)
1. **Roll 角正负方向**: MPU9250 实测 Roll 角正负与左右倾斜的对应关系
   - 若与代码假设相反, 需在 `roll_compensator.c` 里翻转符号
2. **补偿效果**:
   - 地面左右高度差时小车是否能稳定站立
   - 补偿增益 `1.5` 是否合适 (太大可能过补偿, 太小不够)
   - 死区 `2.0°` 是否合适 (太小会频繁抖动)
3. **姿态切换**: 站立/蹲下切换时补偿方向是否正确
4. **主动适应**: 用户主动设置左右腿高度差时是否能稳定

### 待添加功能 (真机验证后)
1. 补偿增益可能需要加到参数表 (App 在线调)
2. LCD UI 显示 Roll 角 + 补偿量 (调试用)
3. 补偿使能开关 (OneNET/App 控制, 默认开启)

## 09:21 LCD 显示 Roll + 配平支持 Roll + Roll 补偿仅在起立状态应用 (0.43, 已编码, 待烧录验证)

### 需求
1. **LCD 显示 Roll 角**：主界面和 MPU 界面都要显示横滚角读数
2. **配平支持 Roll**：配平时同时标定 Pitch 和 Roll 零点
3. **Roll 补偿仅在起立时应用**：避免蹲下/停止等状态误触发补偿

### 实现

#### 1. LCD 显示 Roll 角 (`0.43/main_car/hardware/lcd/lcd_ui.c`)
- **主界面**：新增第 4 行显示 `R:±XX.X°`（Roll 角读数）
- **MPU 界面**：RPY 行改为显示三轴 `R:±XX.X P:±XX.X Y:±XX.X`
- 读取 `mpu9250_get_euler_angles()` 获取 Roll 角并格式化显示

#### 2. 配平支持 Roll (`0.43/main_car/user/control/balance.c`)
- **数据结构**：配平零点从单变量改为结构体
  ```c
  static struct {
      float pitch;
      float roll;
  } s_zero = {0};
  ```
- **采样逻辑**：`balance_calib_step()` 同时累加 `s_calib_sum_p` 和 `s_calib_sum_r`
- **保存逻辑**：`balance_save_zero()` 同时保存 pitch 和 roll 到 NVS
- **日志输出**：`配平开始: 采样 50 个 pitch/roll 点取平均`

#### 3. Roll 补偿仅在起立状态应用
**新增接口** (`0.43/main_car/hardware/servo/servo.c`):
```c
static bool s_balance_mode = false;  // 平衡状态标志

void servo_set_balance_mode(bool enabled) {
    s_balance_mode = enabled;
}
```

**补偿逻辑修改** (`servo_write_hw_ex()`):
```c
if (apply_roll_comp && s_balance_mode) {  // 仅在平衡模式时应用补偿
    roll_comp_calculate(...);
    ...
}
```

**平衡状态管理** (`0.43/main_car/user/control/balance.c`):
- `balance_enable()` (起立): `servo_set_balance_mode(true)` 
- `balance_disable()` (停止): `servo_set_balance_mode(false)`
- `balance_emergency_stop()` (急停): `servo_set_balance_mode(false)`

### 细节
- Roll 补偿**仅在平衡起立状态**应用，蹲下/遥控/停止等状态不应用
- 配平采样 50 次取平均（与原 Pitch 配平逻辑一致）
- LCD 刷新频率 100ms，Roll 角实时显示
- NVS 键名：`"bal_zero_p"` (pitch), `"bal_zero_r"` (roll)

### 待验证
1. LCD 主界面和 MPU 界面是否正确显示 Roll 角
2. 配平是否同时标定 Pitch 和 Roll 零点，并保存到 NVS
3. 起立时 Roll 补偿是否生效
4. 蹲下/停止时 Roll 补偿是否正确停用
5. Roll 角正负方向是否与补偿逻辑一致
