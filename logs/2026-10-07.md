### 二、用户决定的方向：把"方向参数"全删了

| 参数 | 1.1 状态 | 用户决定 | 1.3 归宿 |
|---|---|---|---|
| `ang_zero` | 配平表的零偏备用兜底 | 删 | 配平表已含零偏，无需 |
| `gyro_sign` | 网页滑块，1.1 第八阶段实测 +1 | 删 | 烘焙为 `GYRO_PITCH_SIGN = +1` |
| `bal_sign` | 网页滑块，用户口头说是 -1 | 删 | 烘焙为 `BAL_MOTOR_SIGN = -1` |

**用户原话**：「bal_sign 应该是 -1，其他的方向就对了，直接删除这些
参数的方向调参吧」+「**先删除一些不必要的参数**」。

**为什么是"方向参数"先删**：

- 这三个数**只有拆电机 / 换 MPU 装配方向**才会变。一年碰不到一次。
- 1.1 把这仨设计成网页滑块的初衷是「方向错了能在网页上改，不用重烧」，
  但**用户实际操作里也是要去查日志、量 MPU 才知道对不对**。
  网页滑块相比"改宏重烧"并没有省下多少功夫。
- 反而是被误碰 / 调试时随手一拖 / 多人共用网页时别人误改，**风险大于收益**。

**砍后的**：

```
参数数: 19 → 16
PARAM_DATA_VERSION: 6 → 7 (旧 NVS blob 自动作废)
```

### 三、bal_sign 为什么是 -1

**用户原文**：「bal_sign 应该是 -1」。

**怎么确认的**：1.1 阶段，用户口头说过这个值（之前日志里没记
完整测试过程，1.1 烧录时 `bal_sign` 还是默认值 +1，从 NVS dump
确认过——见第四节）。

**本机的代码默认是 -1**（`balance.h` 的 `BAL_MOTOR_SIGN`）：
- 启动后车往前倒（pitch > 0），平衡环算出正输出
- 乘以 `-1` 后变成负输出
- 电机反转 → 车轮往"倒的反方向"跑 → 反作用力把车**往倒的方向推**？

不对，这里物理上需要想清楚。记一下**控制方向怎么定才正确**：

```
车往前倒 (pitch > 0):
  想要车轮往前跑 (正方向)
  轮子往前跑 → 反作用力把车体往后推 → 抵消前倾
  所以: pitch > 0 → 电机要正转 (跑前面)
  平衡环输出 > 0 → 经 bal_sign 乘到电机
  测得: 启动后车**往倒的反方向**冲 → bal_sign = -1
  意即: 在当前电机接线方向上, 输出 > 0 时电机其实是反转的
```

> 这条靠文字推演还是会有歧义。最稳妥的验证是改线后试一下；
> 但用户说"bal_sign 应该是 -1"是多次试车后得出的结论, 信他。
> 真要复现, 把 `BAL_MOTOR_SIGN` 改成 +1 重烧, 启动后车会
> 往前倒时反而往后冲, 显然不对, 改回 -1。

### 四、NVS dump 验现状（动手前的必要功课）

### 五、扶一下又不动 —— 启动门控的锅

**用户原文**：「现在启动平衡后，用手去扶车，莫名奇妙会动一下，
然后又不会了」。

看到这段时第一反应是 deadzone / PID 死区, 但日志里写过
默认 deadzone = 8, 不算大, 不会让车"扶了没反应"。

**真正的机制**（对照 1.1 第六阶段写过的 arm gate）:

```
STANDBY 状态:
  每 10ms 检查 |pitch| < arm_pitch (8°) 且 |角速度| < arm_rate (20°/s)
  满足时 s_arm_hold_ms 累加, 满 500ms → 进 BALANCING
  任一条件不满足 → 计时清零
```

**扶车时的链路**:

1. 启动时车是稳的 → 进 STANDBY, `arm_ms` 开始累加
2. 用户**用手去扶** → 身体接触改变了 MPU 的角速度测量
3. 角速度**瞬间 > 20°/s**（人手再轻也比机器人自己晃大）
4. `arm_conditions_ok()` 返回 false → `arm_ms` 清零
5. STANDBY 期间电机**始终刹车**（`balance_control_step` 里
   `if (s_state == BAL_STATE_BALANCING) ... else motor_brake_all();`）
6. 用户感觉到"扶一下车抖一下，但电机没真出力"

**为什么之前 1.1 没暴露**：第六阶段写完 arm gate 后用户**没真试过车**。
1.1 第八阶段改完轴向后, 真正在"扶着车 → 启动 → 试输出"的环境下
摸, 才发现这个问题。

**为什么 1.3 不改这个行为**：这是**安全特性**。扶车的动作就是"正在晃"，
如果不检测角速度, 用户一放手车就冲出去, 直接摔。

**正确的用户操作**: 扶正车, 启动, **手完全离开**, 等 `arm_ms` 跳到
500ms, 再去测。

> 1.3 没改代码逻辑, 改的是网页文案:
> "扶正车 → 启动 → 看到门控跳到 500ms 后电机才开始输出"
> 不再提"扶车"。
