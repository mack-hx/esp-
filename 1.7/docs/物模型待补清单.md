## 二、还差 1 项 (不影响使用, 建议补)

### `param_set` 服务的输出参数

现在物模型里 `param_set` 的**输出参数是空的**, 其它 5 个服务 (`calibrate` /
`param_save` / `stand` / `stop`) 都有 `ok` (bool)。
(2026-10-21 傍晚用 `query-thing-model` 复查过, 仍然没补上。)

| 项 | 当前值 | 建议改成 |
|---|---|---|
| 服务 `param_set` → 输出参数 | **空** | 加一个 `ok`, 类型 bool (true/false) |

**为什么要加**: 平台会校验设备应答里的标识符, 多一个它不认识的字段就报
`10415 response invalid`。现在设备是**回空对象** (`"data":{}`) 来适配这个空的输出声明,
调用是成功的; 但平台上这个服务调用记录看不出成功还是失败。

**加完之后**: 设备端改一行即可 (代码里已经写了注释, 改完重新烧录):

```c
/* user/onenet_client/onenet_client.c, param_set 分支 */
service_reply(name, req_id, "{}");              /* 现在这样 (适配空输出声明) */
service_reply(name, req_id, "{\"ok\":true}");    /* 加上 ok 输出后改成这样 */
```

不急着加, 现在就能正常读写参数。

## 三、可以不改的 (只影响后台显示, 不影响功能)

### `speed` 属性的名字和单位

`speed` 现在被当作**移动指令通道**用 (标幺 -1~1), 设备收到就当速度环目标,
同时设备上报的也是当前目标指令值。

| 项 | 当前值 | 建议改成 |
|---|---|---|
| 名称 | 车体速度 | 目标速度指令 |
| 单位 | 米每秒 / m/s | 无量纲 |
| 范围 | -10 ~ 10 | -1 ~ 1 |

不改也能用, 只是后台看到 `speed = 0.6` 时单位写的是 m/s, 有点误导。

## 四、踩过的坑 (记下来, 免得再犯)

1. **平台只认物模型里存在的标识符**。`vx` / `w` 从来没在物模型里出现过,
   平台一律回 `10412 identifier not exist`, 指令根本下发不下去。
   现在移动指令走 `speed` (物模型里真实存在的那个)。
2. **一帧里只要有一个属性不合规, 整帧被拒收**。所以属性上报按 step 分帧:
   角度帧 (`pitch/roll/yaw`, `%.1f`) + 角速度帧 (`gz`, `%.2f`) + 整数帧
   (`motor_l/motor_r/enc_l/enc_r/uptime`) + 字符串帧 (`state`)。
3. **服务应答里不能有多余字段**。物模型没声明的输出标识符, 设备一样发过去,
   平台就判 `response invalid`。
4. **整条 `desired_pull` 只要有一个标识符不存在, 整条 reply 回 2306**。
   所以那里只能问物模型里确定存在的 `speed`。
5. **只读属性别往里写**, 平台会回 `r rw type error`。
6. AccessKey 用**设备级**的那把就行 (跟 ESP32 端同一把), 开放接口照样通。
   `project_id` 选填: 期望值下发和服务调用, 带不带平台都收, 设备都能收到指令。
