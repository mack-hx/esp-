## v0.32 (2026-10-28)

### 位置环默认打开 (本日新增)

- **方向键改成"调目标位置"** (`user/control/balance.c`)
  - 按住前进/后退时, 目标位置按前馈速度往前累积; 松手后目标位置锁死, 位置环一直接管
  - 原来方向键直接给轮速, 车一推就走, 回不来
- **位置环输出整形** (`user/pid/position_pid.h`)
  - 限速 12 rpm/s + 一阶低通 τ=0.2 s
  - 防止位置误差一变就跳变 → 目标倾角跳变 → 车前后摆
- **`pos_kp` 默认 0 → 0.5** (位置环默认打开, **纯 P**), `pos_ki` 保持 0
  - 速度环本身带积分, 位置环再带积分 = 双重积分 → 站直时前后摆 (0.31 抖动结论)
- **参数表版本 17 → 18** (`PARAM_DATA_VERSION` 车端 + `PARAM_VER` App 端同步)
  - 作废旧 NVS blob, 让新默认值真正生效
- 位置环单测改成"跑到稳态再断言" (整形后单拍输出只有稳态的千分之几)

### 设备端

- **`bal_kd` 默认值 1.5 -> 0.4 真正生效** (0.31 的遗留问题)
  - 0.31 里车端 `param.c` 已经把默认值改成 0.4, 但 **App 侧 `paramDef.js` 还停在 1.5**
  - App 下发参数时用的是 App 里的值 -> 车照旧按 kd=1.5 跑 -> 一起立就满幅打摆
  - 本版两边同步改成 0.4, 并加了 `scripts/check_param_sync.py` 自动比对
- **参数表版本 16 -> 17 -> 18** (`PARAM_DATA_VERSION`)
  - 只改默认值不升版本的话, NVS 里的旧 blob 仍然有效, `kd=1.5` 照旧生效
  - 升版本作废旧 blob -> 所有参数回到出厂默认 (`kp=12` / `ki=0.5` / **`kd=0.4`** / 位置环开)
  - WARN **烧录后必须重新配平**, 0.31 之前在 App 上调过的参数会丢
- **控制回路跟踪拆成独立组件 `user/trace/`**
  - 采集 (`trace_push`, 控制任务调, 几百纳秒, 不碰串口) 与输出 (独立任务, 钉 core 0) 分离
  - 原因: 在控制任务里 `printf` 一百多字节要几毫秒, 等于给平衡内环加几十毫秒延迟,
    内环本来就在相位裕度边缘, 这一下足以把车顶出振荡, 测出来的数据也被打印污染
  - 环形缓冲 600 条 x 10ms = **6 秒**历史; 状态离开"平衡中"时自动回灌串口
- **控制台波特率 115200 -> 230400**
  - 100Hz 的 TRACE 输出 = 12.5KB/s, 115200 只有 11.5KB/s -> 丢行, 采样率就假了
  - 顺带修了一个坑: `ESP_CONSOLE_UART_BAUDRATE` 只有开了
    `ESP_CONSOLE_UART_CUSTOM` 才有 prompt, 否则 kconfig 每次编译都把它重置回 115200
    (直接改 `sdkconfig` 白改)
- `pos_kp` 的显示小数位 2 -> 1 (step 是 0.1, App 侧本来就是 1)

### App 端

- `bal_kd` 默认值 1.5 -> **0.4**, hint 改成"不要再加大"并附上自激机理
- `pos_kp` 默认 0 -> **0.5** (位置环默认打开), `pos_ki` 保持 0
- `PARAM_VER` 16 -> **17 -> 18** (跟车端同步)
- 版本号 0.31.0 -> 0.32.0 (`versionCode` 141 -> 142)

### 工具链

- `scripts/check_param_sync.py` (新): 自动比对车端 `param.c` 与 App `paramDef.js`
  的 def/min/max/step/dec/grp 逐项一致 + 版本号一致。**这类脱节已经发生过两次**
  (2026-10-26 速度环那次事故、0.31 的 bal_kd 这次), 以后改参数表先跑它
- `scripts/run_tests.sh` (新): 一条命令跑完 5 个离线单元测试 + 参数表一致性 + App JS 语法检查
- `scripts/capture_trace.py`: 改用通用的 `key=value` 解析 (固件加字段不用改脚本),
  串口设备改成参数 / `TRACE_PORT` 环境变量 / 自动挑 `/dev/cu.usbmodem*`
- `scripts/analyze_trace.py`: 改用列名取列 (不再写死下标), 段时长从时间戳算
  (不再假设 100ms 采样)
- `scripts/fft_trace.py`: **修了两个真 bug**
  - 列错位一列 (`names` 排除了 `t_ms`, 取列时又没跳第 0 列 -> 整张表错位,
    `st` 读到的是 `pos_out`, 永远找不到 BALANCING 段)
  - 段切得太碎 (用 `|out| > 5` 当门槛, 但振荡信号的输出本来就在 0 附近来回穿,
    每段被切成几十片 -> **恰好在真抖的时候报告"找到 0 段抖动"**)
  - 改成按状态切连续段

### 验证状态

- `pio run` SUCCESS, RAM 25.1% (82,212 / 327,680), Flash 28.3% (1,039,581 / 3,670,016)
- 离线单元测试: `trim` 67 / `pid` 29 / `param` **123** / `speed_pid` 14 / `position_pid` **10**, 全绿
- 参数表一致性: 20 项逐项一致, 版本号 18 = 18
- App JS 语法 + `manifest.json` / `pages.json` JSON 解析: 通过

### 真机待验证

- [ ] 烧录 0.32 后**必须重新配平** (参数表作废, 配平表 / 配平零点也跟着作废)
- [ ] App 参数页显示 `bal_kd = 0.4` (不是 1.5), `pos_kp = 0.5`
- [ ] 定轴静置 30 秒, 确认不再一起立就满幅打摆
- [ ] 推一把车, 确认它能自己回原位 (位置环生效)
- [ ] 采样率验证: 新 TRACE 格式下 `capture_trace.py` 抓的行数应接近 100 行/秒

### 已知风险

- **里程计漂移**: 站住不动时轮子有微小位移, 里程计累积成位置误差, 位置环以为"偏了"
  去追 → 车可能慢慢挪位置。这是纯编码器位置保持的固有短板, 死区 1 cm + 小 kp 只能压住,
  根治要外部参照 (视觉/地标) 或更可靠的编码器
