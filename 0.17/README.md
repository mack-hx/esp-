# ESP32-S3R8N8 平衡轮腿机器人 - 版本 0.17

## 0.17 相对 0.16 改了什么

**打通 App ↔ OneNet ↔ 小车 的全链路**, 并把调参从网页搬到了 App。

0.16 只是"设备能连 OneNet 并上报属性", 但 App 发出去的指令平台根本收不到。
0.17 把这条链路从头到尾打通并逐项实测通过 (详见 `../logs/2026-10-21.md`)。

### 设备端

- 修 4 个 bug: 服务应答随机丢失 (static 缓冲区没截断)、属性上报 step 不对齐整帧被拒、
  事件参数单位错误、平台拒收日志刷屏
- 属性上报按 step 分帧 (角度帧 / 角速度帧 / 整数帧 / 字符串帧)
- 新增上报: 灯 / 电磁铁 / 舵机角度 / 开关状态, 1s 一帧
- 移动指令同时认 `speed` (物模型里真实存在的) 和 `vx` (万一以后补上)

### App 端

- 移动指令从 `{vx, w}` 改成 `{speed}` (物模型里根本没有 `vx` / `w`)
- 统一错误出口: 单条指令失败不再把整条连接判成"错误" (只有鉴权类错误才算)
- 平台返回 `code != 0` 一律抛异常 (以前 10415 被当成成功)
- 浏览器刷新后自动重连, 不用每次去连接页手点验证
- 参数表跟设备端 `param.c` 逐项对齐 (原来 6 项对不上, 保存参数根本传不到车上)
- 删掉状态页里那份重复的 PID 编辑器 (按一下保存就把车的 `bal_ki` 从 12 改成 0)

### 平台侧

用户在 OneNet 后台补齐了物模型: 灯 / 电磁铁 / 舵机 / 开关 / `param_get` / `param_set` /
`param_save`。还差一项: `param_set` 的输出参数是空的, 详见 `docs/物模型待补清单.md`。

## 整体架构

```
┌────────────┐   MQTT (OneNet 物模型)   ┌─────────────────┐
│  ESP32S3   │ ───────────────────────▶ │  OneNet 平台     │
│  0.17/user  │ ◀─────────────────────── │  iot-api.heclouds│
└────────────┘   property/set, 服务调用   └─────────────────┘
      │                                                  ▲
      │ 10ms 控制环                                     │ HTTPS 开放接口
      ▼                                                  │
┌────────────┐                                    ┌────────────┐
│ 编码器/电机 │                                    │  App (H5)  │
│  舵机/IMU  │                                    │  0.17/app   │
└────────────┘                                    └────────────┘
```

- **设备端**: ESP-IDF (PlatformIO), 控制环 10ms, MQTT 连 OneNet 物模型
- **平台**: OneNet Studio 物模型, 提供属性 / 服务 / 事件
- **App**: uni-app (Vue3), H5 为主, 走 OneNet 开放接口 (HTTPS)

## 驱动方式: 双轮同向 (不是差速)

平衡靠两轮**一起**朝倒的方向跑, 用轮子的牵引力把重心甩到轮轴上方 ——
标准 inverted-pendulum-on-wheels 平衡车做法。

差速只能让车**原地转**, 产生不了托住重心所需的平移加速度, 扶不住倒下的车身。

| 常量 | 值 | 说明 |
|---|---|---|
| `BAL_MOTOR_SIGN` | `-1` | 0.11 真机试车实测: 启动后车往倒的反方向冲, 反相就对了 |
| `GYRO_PITCH_SIGN` | `+1` | 0.11 实测: 前倾 `gx` 为正、Pitch 也为正 |
| `PITCH_ZERO_REF` | `90.0°` | 2026-10-15 新四连杆结构: 水平位 az≈1, ay≈0 → atan2(1,0)=90° |

这三个数**只有拆电机 / 换 MPU 装配方向**才会变, 一年也碰不到一次。
留成网页滑块反而是隐患: 被误碰 / 不小心存盘, 下次烧录就翻车。

## 控制结构

```
速度环 (外环, 慢)  ──> 目标倾角 target_pitch (°)
     │
     ▼
平衡环 (内环, 快)  ──> 电机输出 (%)  ──>  两轮同向

输入: MPU 姿态角/角速度 + 编码器轮速
输出: 电机 A/B PWM (两轮同向) + 两路舵机
```

**控制周期 10ms 单环串级**, 用 `vTaskDelayUntil` 保证周期稳定。

## 姿态读数的修正链

```
pitch_修正 = pitch_原始 − trim_pitch(舵机角, 舵机中心角)
```

`trim_pitch` 是配平表 (`user/trim`)。在信号侧减而不是在目标倾角上加, 这样
摔倒判定 (`|pitch| > ang_limit`) 也跟着被修正, 否则腿弯多了会误判摔倒。

## 状态机

```
IDLE ──(启动)──> STANDBY ──(连续稳定 arm_time)──> BALANCING
                                                    │
                                               (倾角超限)
                                                    ▼
                                                 FALLEN
                                                    │
                                              (人把车扶正)
                                                    ▼
                                                 STANDBY
```

- **IDLE**: 未启动, 电机刹车
- **STANDBY**: 已启动但还没进平衡 (等姿态连续稳定 = 启动门控)
- **BALANCING**: 控制中
- **FALLEN**: 判定摔倒, 电机已停、积分已清, **等扶正后自动回 STANDBY**

**启动门控**: 必须连续满足 `|pitch| < arm_pitch` 且 `|角速度| < arm_rate`
达 `arm_time` 毫秒才放行。原因是"没超限"和"稳得住"完全是两回事 ——
被扶着还在晃就放行, 电机一接手晃得更厉害, 直接摔。

**摔倒判定**: `|pitch| > ang_limit` (默认 25°)。宁可误停也不能不停。

## 硬件映射

编号统一为「物理左 = 1, 物理右 = 2」。

| 实物位置 | 编码器 | 电机 | 舵机 |
|---|---|---|---|
| 左 | `ENCODER_1` = GPIO45/46 | `MOTOR_A` = PWMA (GPIO15) | `SERVO_1` = GPIO14 |
| 右 | `ENCODER_2` = GPIO41/42 | `MOTOR_B` = PWMB (GPIO16) | `SERVO_2` = GPIO13 |

## 调参方式

0.14 起调参**改走 OneNet App**, 不再有网页调参服务器
(`http://192.168.4.1` 那个页面在 0.14 就删了, 0.17 里只剩 AP 配网页)。

- App "参数"页: 拉取 (显示车上的真实值) → 改滑块 → 保存 → 落盘 NVS
- 参数表 16 项, 定义见 `user/param/param.c` (`PARAM_DATA_VERSION 7`),
  App 侧镜像在 `app/common/paramDef.js` —— **改了一边必须同步另一边**
- 屏上也能看状态 (菜单 → 平衡控制页), 但不能改参数

## 下一步要做的事

1. **先做配平标定** (不标定腿一动车就歪, 永远站不起来)
2. **试车前把 `motor_max` 压到 25 以内** (默认 30 已经是保守值)
3. 扶正车 → 启动 → 看到启动门控计时满 `arm_time` 后电机才开始输出
4. 观察车往**倒的方向**冲 = 方向正确 (已烘焙在 `balance.h` 里)
5. 方向对了, 再慢慢加 `bal_kp`, 找到能站住的 Kp
6. 调 `bal_ki` (消稳态偏差)、`bal_kd` (消振荡)
7. **全程扶着车, 随时准备断电**
