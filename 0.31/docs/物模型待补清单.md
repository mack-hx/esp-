## 二、还差 4 项 (必须去后台手动加, 否则 App 点按钮报 10412)

**4 个配平标定服务在 OneNet 后台的物模型里完全不存在**, 设备端代码已经有了
(`user/onenet_client/onenet_client.c` 里 `trim_record` / `trim_save` / `trim_clear` / `trim_get`
四个分支), 但平台不认这些标识符, App 点对应按钮时平台一律回
`10412 identifier not exist`, 指令根本下发不下去, **必须人工去后台加**。

| 标识符 | 输入参数 | 输出参数 | 说明 |
|---|---|---|---|
| `trim_record` | (无) | `values: string` | 记一个配平表标定点 (当前舵机角 → 当前原始 pitch) |
| `trim_save` | (无) | `values: string` | 配平表落盘 (NVS), 断电不丢 |
| `trim_clear` | (无) | `values: string` | 清空配平表并落盘 (换机械结构后用) |
| `trim_get` | (无) | `values: string` | 读回配平表 (JSON 字符串, 和 `param_get` 一个格式) |

**后台怎么配**:

1. 产品页面 → 物模型 → **添加服务**, 4 个服务各建一个。
2. **服务标识符**填上表的标识符, 一字不差 (`trim_record` / `trim_save` /
   `trim_clear` / `trim_get`), 区分大小写。
3. **输入参数**: 4 个都**不加**。
4. **输出参数**: 4 个都只加**一个** `values`, 类型 **string (字符串)**,
   长度按上表给的值填 (记档点 256 / 落盘 64 / 清空 64 / 读表 1024,
   长度只是上限, 填大一点也行)。
   ⚠ **千万不要配成 `ok` (bool)**: 设备端这 4 个服务回的字段名就是 `values`,
   平台物模型里没声明 `values` 就会判应答不合法, 报 `10415 response invalid`。
5. 保存后用 `GET /thingmodel/query-thing-model?product_id=6YlUqr9lue` 复查一遍,
   确认 4 个标识符都在。

> 设备端回的内容: 3 个写操作回一句人话 (`ok, n=3` / `ok, cleared` / `ok, phi=90, pitch=1.20, n=3`),
> `trim_get` 回配平表的 JSON (和 `param_get` 一样的格式), 都放在 `values` 这个字符串里。

## 三、还差 1 项 (不影响使用, 建议补)

### `param_set` 服务的输出参数

现在物模型里 `param_set` 的**输出参数是空的**, 其它服务里
`stand` / `stop` / `calibrate` / `param_save` 回 `ok` (bool),
`param_get` 和 4 个 trim 服务回 `values` (string)。
(2026-10-26 复查过, `param_set` 仍然没补上输出参数。)

| 项 | 当前值 | 建议改成 |
|---|---|---|
| 服务 `param_set` → 输出参数 | **空** | 加一个 `ok`, 类型 bool (true/false) |

**为什么要加**: 平台会校验设备应答里的标识符, 多一个它不认识的字段就报
`10415 response invalid`。现在设备是**回空对象** (`"data":{}`) 来适配这个空的输出声明,
调用是成功的; 但平台上这个服务调用记录看不出成功还是失败。

**加完之后**: 设备端改一行即可 (代码里已经写了注释, 改完重新烧录):

```c
/* user/onenet_client/onenet_client.c, param_set 分支 */
service_reply(name, req_id, "{}");              /* 现在这样 (适配空输出声明) */
service_reply(name, req_id, "{\"ok\":true}");    /* 加上 ok 输出后改成这样 */
```

不急着加, 现在就能正常读写参数。

## 四、可以不改的 (只影响后台显示, 不影响功能)

### `speed` 属性的名字和单位

`speed` 现在装的是**打包指令** (方向 + 档位, 编码见 `../app/onenet_物模型.md` 2.4),
设备上报的也是当前指令原值。

| 项 | 当前值 | 建议改成 |
|---|---|---|
| 名称 | 车体速度 | 遥控指令 |
| 单位 | 米每秒 / m/s | 无量纲 |

不改也能用, 只是后台看到 `speed = 0.6` 时单位写的是 m/s, 有点误导。

### 想新增属性但平台开放接口不提供 (2026-10-24 实测)

OneNet 开放接口只有 `query-thing-model` (查询), **没有新增/修改物模型的接口**;
控制台新增属性要手机号 + 短信登录, 自动化流程进不去。
所以想在后台加"独立的方向属性 / 档位属性"是做不到的, 只能沿用 `speed` 打包。

## 五、踩过的坑 (记下来, 免得再犯)

1. **平台只认物模型里存在的标识符**。`vx` / `w` 从来没在物模型里出现过,
   平台一律回 `10412 identifier not exist`, 指令根本下发不下去。
   现在移动指令走 `speed` (物模型里真实存在的那个)。
   4 个 trim 服务现在也踩在同一个坑里 —— 后台没加, App 点按钮就是 10412。
2. **一帧里只要有一个属性不合规, 整帧被拒收**。所以属性上报按 step 分帧:
   角度帧 (`pitch/roll/yaw`, `%.1f`) + 角速度帧 (`gz`, `%.2f`) + 整数帧
   (`motor_l/motor_r/enc_l/enc_r/uptime`) + 字符串帧 (`state`)。
3. **服务应答里不能有多余字段**。物模型没声明的输出标识符, 设备一样发过去,
   平台就判 `response invalid`。
4. **整条 `desired_pull` 只要有一个标识符不存在, 整条 reply 回 2306**。
   所以那里只能问物模型里确定存在的 `speed`。
5. **只读属性别往里写**, 平台会回 `r rw type error`。
6. AccessKey 用**设备级**的那把就行 (跟 ESP32 端同一把), 开放接口照样通。
   `project_id` 选填: 期望值下发和服务调用, 带不带平台都收, 设备都能收到指令。
